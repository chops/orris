#+TITLE: Observe deadline actuation under the Run.Worker fence
#+PROPERTY: status delivered contract

* Implementation status
Delivered. =AiOrchestrator.Effects= honours =opts[:adapter_runner]= for =Effect.Observe= (=observe_through/3=), maps a
runner =:expired= to =Observation.TimedOut= from the owner's retained intent, and raises =Effects.AdapterFailure=
for a validated closed diagnostic; =AiOrchestrator.Effects.AdapterRunner= (=run/1=, =diagnostic?/1=) is the shared
runner boundary. =AiOrchestrator.Run.Worker= takes a zero-arity bootstrap closure in =start_link/2=, owns a linked
=Task.Supervisor=, arms the fence once per fenced execute through =AiOrchestrator.Run.DeadlineFence=, runs the
adapter in a supervised task and kills it when the fence is due. The same fence has since been generalised to
=Dispatch= / =ReconcileSend= (see =delivery-deadline.org=); the Worker's =observe_fence_kinds= seam defaults to
=[Effect.Observe]= so this document's fact stream is unchanged. Rows C-1..C-10 and O-1..O-18 live in
=test/run/observe_deadline_red_test.exs=; the Port-retention baseline is
=test/run/observe_port_retention_control_test.exs=; the imported carrier-validation probe is
=test/run/observe_green_review_test.exs=; the FixedClock monotonic decoupling controls are
=test/clock/fixed_clock_decoupling_test.exs=. Nothing here claims settle responsiveness, OS/remote containment, or
deadline coverage for gate effects, =SnapshotArtifact=, =ReadReview= or =Timer=.

* Scope
This contract covers ONLY =Effect.Observe= (=dispatch_module.observe/2=). =Timer= is an owner-side =Process.sleep=;
gate effects, =SnapshotArtifact=, =ReadReview= and =Timer= are explicitly UNCOVERED. The unit retires one specific
gap: a blocked non-cooperative observe adapter. No runtime-wide deadline coverage is claimed.

* Source facts the contract rests on
- =Run.Worker.handle_info({:execute, cap, gen, ref, intent, receipt})= calls =Effects.execute= SYNCHRONOUSLY for a
  generic effect; =Effects.execute= -> =run_effect= -> =guarded(runtime, fn -> adapter ... end)= ->
  =adapter(%Effect.Observe{command, deadline_unix}, opts)= = =dispatch_module(opts).observe(command,
  observe_opts(deadline_unix, opts))=, where =observe_opts= caps the adapter's =observe_timeout_ms= to the
  remaining window and =dispatch_opts(opts)= is exactly =opts[:dispatch_opts]=.
- Raw adapter results map in =Effects.observe/3=: ={:ok, artifact}= -> =ArtifactObserved=, ={:blocked, r}= ->
  =Blocked=, ={:pending, d}= -> =Pending=, ={:error, map}= -> =ObserveFailed=, other ->
  =ObserveFailed(invalid_return)=. =Observation.TimedOut= is ADMISSIBLE for =Observe=; before this unit it had no
  producer anywhere in lib (only its definition, the Diagnostic list and the reducer's =unwrap=).
- COOPERATIVE baseline: =LocalPane.observe= polls until =monotonic_ms >= deadline_ms= and =retry_observation=
  returns ={:error, %{"reason" => "observation_timeout", "last_observation" => reason}}= -> =ObserveFailed= ->
  =unwrap= ={:error, reason}= -> =assignment_observed/4= or =artifact_observed/5= -> =ret(state, {:error,
  reason})= -> with an empty stack =halt(state, value)= -> =Host.advance= returns ={:halt, {:error, rejection}}=.
  No event is emitted by those clauses. What the Executor/Server finally return and what the durable prefix
  contains after that halt is MEASURED by control C-2 from a real run (a Host halt surfaced as the Server's cached
  =:failed= result, no exit, no event), never assumed.
- Raw adapter failures: =guarded= re-raises as =Effects.Interrupted=; the Worker's execute boundary closes it
  (kind, class, digest, frames, cleanup summary after =Effects.settle=) and answers =effect_failed=; the Server
  EXITS =run_step_failed= on it, it never reaches the reducer (=Server.closed_diagnostic?= admits exactly five keys
  and kind =error|exit|throw=).
- The Worker cannot service =settle= or system messages while inside =Effects.execute= (control C-1). An adapter
  runner invoked INSIDE =Effects.execute= is a nested receive while =handle_info= is active: it does NOT free the
  Worker's loop; only the runner's own selective receive dequeues during the wait. This unit pins that model; it
  claims no settle responsiveness.

* Interface (fence, runner, expiry model)
- =adapter_runner= seam on =Effects= inputs (=opts[:adapter_runner]=; default: invoke the closure in the calling
  process with the EXISTING =guarded= / =Interrupted= / Host semantics, byte-identical behaviour). Used at the
  =Effect.Observe= adapter site; the seam wraps the RAW invocation
  =fn -> dispatch_module(opts).observe(command, observe_opts(deadline_unix, opts)) end=. The raw -> =Observation=
  mapping stays in =Effects.observe/3=.
- Runner result grammar, DISJOINT: ={:ok, raw}= (the adapter returned; =raw= may itself be ={:error, map}=, which
  then takes the existing =ObserveFailed= mapping), ={:failed, diagnostic}= (a raw =raise= / =throw= / =exit=
  inside the task, closed INSIDE the task as the existing closed diagnostic: =kind= error|exit|throw, =class=
  =Diagnostic.result_class=, =digest=, =frames= = the MEASURED task stack depth; depth-parity differences from the
  in-process path are disclosed, never fabricated), =:expired= (the owner's fence selected expiration before any
  result; the expiry data, =deadline_unix=, comes from the OWNER's retained intent/fence, never from the task or a
  supplied map). A malformed runner envelope fails closed on the normal path and never enters the precomputed
  diagnostic path by map shape alone.
- Owner-side failure carrier within the root =Effects= boundary: a small typed =Effects.AdapterFailure= holding
  ONLY the validated closed diagnostic, raised by =Effects= under =guarded= so the existing =Interrupted= adds the
  latest OWNER Runtime; the Worker handles that tagged case by settling that runtime and building the existing
  five-key closed failure plus cleanup, preserving the original kind/class (never re-hashing the precomputed
  diagnostic as if it were the original cause). No public diagnostic field, kind or EventData change.
- Expiration mapping: =:expired= is mapped by =Effects= to =Observation.TimedOut{assignment_id, deadline_unix:
  <the owner's retained intent deadline>, now: now(opts)}=, making this unit the FIRST producer of that admissible
  type (disclosed: it is not a previously emitted baseline). The cooperative shape (=ObserveFailed= with
  =observation_timeout= + =last_observation=) is UNCHANGED and remains a separate baseline; the expiry shape is
  distinct (unwrap = =observation_timeout= + =deadline_unix=) and is disclosed as such; no =last_observation= and
  no event is fabricated. The full-path baseline (what the Executor returns and what the durable prefix holds
  after the halt) is measured before any no-event assertion.
- Worker-owned fence: the earliest AVAILABLE deadline is the intent's =Effect.Observe.deadline_unix= as the
  reducer built it (its relation to the accepted =assignment_requested= prefix is pinned by a baseline control);
  armed ONCE at the VALIDATED Worker =:execute= dequeue, BEFORE adapter invocation, from one =Clock.unix_now= and
  one =Clock.monotonic_ms= of the SAME configured owner-side Clock (no system-clock bypass); the absolute due
  instant and the bounded wait cap are retained; already due => =:expired= with ZERO adapter invocations; late
  admission consumes the REMAINING deadline, never a fresh =timeout_s=; identity = the Server's =cap/gen/ref= of
  that request, applied on every dequeue.
- Owner-side runner RECEIVE loop: =Effects= stays SYNCHRONOUS in the Worker; the runner's own selective receive
  handles ONLY the correlated task facts (reply, DOWN) and its timer, then returns to the existing Worker flow;
  other settle/system messages may stay queued until it returns. No claim that the task launch frees the outer
  GenServer loop; this unit delivers deadline responsiveness and truthful cleanup, not an async rewrite.
- Worker-internal linked =Task.Supervisor= started in =Worker.init=: the observe task runs under it with the GO
  handshake and an independent death monitor; task input = the raw closure and the deadline only (no Runtime,
  Interrupted, gate handle, owner memo). Partial start (=Task.Supervisor.start_link= failure) fails =Worker.init=;
  the Server's existing pre-admission =run_worker_start_failed= is source-measured as a control before being
  pinned; owner hard death BEFORE GO is witnessed; no outer topology change; no global =trap_exit=.
- Winner and facts: the timeout winner is retained; an actual raced raw reply is acknowledged/consumed with CLOSED
  metadata only (presence, outcome class, correlated identity) and never applied to the reducer nor read as
  settlement; a result dequeued first preserves normal behaviour with no kill; an ordinary task-error result wins
  if first; due wake, kill request, observed DOWN, shutdown return and late-result presence are SEPARATE facts;
  early / foreign / duplicate wakes never kill; a no-reply death is a truthful closed failure with current-op
  correlation retained through completion or death proof.
- No deliver/reconcile is ever called by this path (measured with counters); a task that dies without a reply
  yields the existing closed failure + join facts, never a hang, never an observed result; a late raw result
  after a selected expiration never becomes an observation, never completes the assignment, never releases a
  lease as success, never resets the winner; a killed task proves nothing about OS or remote work.

* Boundary decisions
- Default direct =Effects.execute= (no =adapter_runner=) keeps EXISTING behaviour in every respect: no arming, no
  expiry, the adapter runs in the calling process. Expiry is owned by the WORKER: it arms at its validated
  =:execute= dequeue and decides expiry before invoking =Effects=. Consequence: an already-due deadline at the
  product Worker yields =Observation.TimedOut= with ZERO task starts and ZERO adapter entries AND the runner seam
  is NOT invoked at all (a runner call is not a task start, but not invoking it is the simplest closed rule); a
  direct =Effects.execute= with a runner and an already-due deadline still invokes the runner (Effects does not
  arm) - that is the boundary, pinned by O-1 and O-3 respectively.
- The owner Clock is the configured =:clock= seam; arming reads it EXACTLY once each for =unix_now= and
  =monotonic_ms= (call counts witnessed by a counting Clock); no second owner read, no system-clock bypass; the
  chunk cap is =opts[:observe_fence_cap_ms]= (test-only override; runtime default =60_000= ms, supplied to
  DeadlineFence); every early wake carries the SAME =due_ms=; an independent oracle recomputes the expected due and
  each expected wait from the same scripted values with =Run.DeadlineFence= directly.

* Engineering decisions (D1..D4)
- D1: at the Worker, already due => no runner invocation, no task start, no adapter entry; direct =Effects=
  unchanged. On a resume of an already-expired prefix the same rule holds (control C-3 below).
- D2 seam transport: =Run.Worker.start_link(server, bootstrap)= where =bootstrap= is a ZERO-ARITY CLOSURE (never a
  map, never a raw MFA): the child start MFA carries only the closure, so supervisor start/crash reports render
  =#Function<...>= and no payload; the closure is EXECUTED inside =init= under the closed failure boundary and may
  yield ONLY the closed keys =:task_supervisor_start=, =:fence_observer=, =:fence_hold=, =:fence_cap_ms= (a later
  unit added =:retention_observer=; an unknown key refuses at init); the Server builds the closure at Worker birth
  from its own =config.opts=; =format_status= redacts the bootstrap and the yielded seams; existing
  =worker_module= doubles and the Server protocol are preserved.
- D3 (no deferral): owner Port/memo retention is witnessed with a test GateDouble WRAPPER that opens =/bin/cat= in
  =prepare= and asserts the same-process memo and Port in =abandon= (a baseline helper imported from review); no
  native guardian needed. Control C-8 proves a real =PrepareGate= alone succeeds under the standalone admitted
  Worker BEFORE O-11b is asserted.
- D4: the frames relation is EQUALITY against an INDEPENDENT measurement of the SAME raw failure site: the test
  adapter wraps its raw =raise= / =throw= / =exit= in a test-owned =try ... catch k, r= that records
  =length(__STACKTRACE__)= to the test and re-raises the ORIGINAL stack with =:erlang.raise(k, r, stack)=; the
  production diagnostic's =frames= must equal that observed length (a constant-frames mutant fails). The untouched
  raw-failure canary rows (C-5 parity, O-6b) stay separate. The public runner boundary
  =AiOrchestrator.Effects.AdapterRunner.run(closure) -> {:ok, raw} | {:failed, diagnostic}= remains the shared
  small boundary but is NOT the reference. An earlier =<= 4= tolerance was withdrawn.

* Test-only seams (never set in production; default nil)
- =observe_fence_observer= (pid): facts ={:observe_fence, worker, %{op: %{cap, gen, ref}, task: %{ref, pid} | nil,
  fact}}= for =:task_supervisor= (pid, sent once at Worker init), ={:armed, %{deadline_unix, due_ms}}=,
  ={:task_started, pid}=, ={:early, %{wait_ms, due_ms}}=, =:due=, =:kill_requested=, ={:shutdown_return, :ok_reply
  | :exit | nil}=, ={:death, class}=, ={:late_result, :stale}=, ={:stale, :foreign | :duplicate | :retired}=.
  Facts also carry =kind:= (the intent struct) and =observe_fence_kinds= (default =[Effect.Observe]=) selects
  which kinds report (see =delivery-deadline.org=).
- =observe_fence_hold= is a plain map with optional =:before_go= and =:after_expiry= pid values. An absent stage
  means no hold there; a bare pid, unknown stage or non-pid controller refuses at bootstrap/admit validation. The
  bootstrap's =:fence_hold= carries this same shape. The Worker sends ={:observe_fence_held, worker, token, %{op,
  task, stage}}= and waits without a timeout for ={:observe_fence_proceed, token}=, monitoring that stage's
  controller. The pre-GO stage is after task allocation but before execution; controller loss joins the task
  without granting GO. The after-expiry stage is after expiry selection but before shutdown; controller loss
  proceeds only to that selected shutdown. Full-subtree expiry rows select only =:after_expiry=.
- Timer wake message: the Worker's own timer sends ={:observe_fence_wake, %{cap, gen, ref}}= to the Worker; a test
  may inject the same shape to deliver a foreign, duplicate or retired wake.
- =observe_task_supervisor_start= (zero-arity fun): replaces =Task.Supervisor.start_link= in =Worker.init=
  (partial-start witness).

  with =AdapterRunner.diagnostic?/1= before honouring it.
