* Scope (review corrections S-M1..S-M5 applied)
Only two things: =Writer.verified/1= and the smallest Writer-owned conditional-append fence. No reservation or
terminal producer, restart loop, timeout actuator, budget schema/version change, daemon mounting or topology
change. =Writer.opened/1= keeps its cached startup-view semantics; no consumer changes. Boundary stated
explicitly: the UNFENCED append's threat model is unchanged - arbitrary external filesystem writers are outside it;
the snapshot's job is to detect what the disk says at snapshot time, not to police concurrent external writers.

* Frozen shapes (smallest)
#+begin_src elixir
# Writer.verified(pid) :: {:ok, snapshot()} | {:error, refusal()}
snapshot :: %{
  lines: [binary()],                 # the ACCEPTED verified lines, as Reader/opened already return (S-M1): the
                                     # fresh prefix a recovery decision folds, from THIS same operation
  seq: non_neg_integer(),            # == length(lines)
  last_line_sha256: String.t(),      # hash OF the last accepted line (Chain anchor when empty)
  envelope_version: 0 | 1 | 2,
  version_2_from: pos_integer() | nil,
  receipt: %{seq, line_sha256} | nil,# the actual receipt; absence may be legitimate or require reported repair
  repair: Chain.plan() | nil,        # a PENDING plan the read-only snapshot reports and never executes
  generation: pos_integer(),         # the lock generation this Writer holds
  token: token() | nil              # no append capability while repair is pending
}
token :: %{seq, last_line_sha256, generation, ref :: reference()}   # authenticated as a WHOLE
# Writer.append(pid, event, fence: token) :: {:ok, stamped} | {:error, refusal()}
#+end_src
Token lifecycle (S-M8; exactly ONE retained entry, the most recently MINTED complete token):
| Situation | =verified/1= | fenced append with the retained token | any other token |
|-----------+--------------+---------------------------------------+-----------------|
| healthy head, no append since minting | returns the SAME token (idempotent) | admitted (then the head advances; the token stays retained) | =snapshot_foreign= |
| an append advanced the head; no new snapshot yet | mints a NEW token and replaces the entry | the retained one authenticates and fails =snapshot_stale= | =snapshot_foreign= |
| after the replacement | - | the OLD token is unrecognized: =snapshot_foreign= | - |
| a retained token with any field mutated | - | =snapshot_foreign= (whole-token equality) | - |
| after a failed or pending-repair verification | the entry is CLEARED (=token: nil= when pending) | =snapshot_foreign= | =snapshot_foreign= |
No historical registry, no growth. Authentication compares the COMPLETE token (ref AND seq/hash/generation)
against the single retained entry, never a caller-supplied head alone.

Pending repair is EVIDENCE, not append authority (S-M7): when the re-read reports a pending plan (receipt trailing
by one, or a torn tail) =verified/1= still succeeds read-only with the accepted lines, the ACTUAL receipt (or
absent) and the pending plan, but =token: nil= and the retained entry is cleared; a fenced append then has no
capability until the existing reopen authority repairs the journal and a new healthy snapshot is minted. The
Reader's absence rules apply: a FIRST v2 line without a receipt is repairable (fewer than two chained lines):
absent receipt + pending plan + no token; two or more chained v2 lines without a receipt are refused
(=snapshot_corrupt= reason =receipt_missing=); empty / legacy absence stays legitimate (token minted).

* Verification (S-M5)
=verified/1= RE-READS =events.jsonl= and =events.head= through the Writer's Fs seam (both reads are traceable),
runs =Chain.verify= + =Chain.reconcile= (the Reader's rules), validates every complete line, and then REQUIRES
the accepted result to equal the in-memory head. It executes no repair (a pending plan is reported as =repair=).
Supported legacy/envelope prefixes that =Writer.open= accepts are accepted here too (envelope 1: receipt nil).
Read faults are independent per source: a journal-read fault stops the verification at the journal (the receipt
is never read, as the Reader does today); a receipt-read fault is reachable only when the journal read succeeds
(S-M6). The event corpus of the rows is the existing valid fixture grammar, with a baseline acceptance control.

* Error domain (closed; strict fields; no journal/prompt/adapter bytes)
| clause | when | fields |
|--------+------+--------|
| =writer_failed= | the Writer is warm-failed (an earlier stage failure) | =cause= = EXACTLY =%{clause: "append_failed", stage: stage}= - the seam =detail= bytes of the legacy append error are NOT carried (S-M10) |
| =snapshot_unreadable= | the journal or the receipt cannot be read | =source= ("journal" / "receipt"), =stage= ("read") - the seam reason is NOT echoed |
| =snapshot_corrupt= | Chain/Reader refuse the disk state (chain break, torn beyond repair, receipt decode / missing on a v2 tail / beyond tail / hash mismatch, line validation) | =reason= = Chain/Reader clause only (e.g. =receipt_missing=, =receipt_hash_mismatch=, =chain_break=) |
| =snapshot_divergent= | disk verifies but its head differs from the in-memory head | =disk_seq=, =memory_seq= |
| =fence_invalid= | the option list is not exactly =[fence: token]= (=field= "options": unknown or duplicated key, bare element, non-atom key, improper list - refused by structure, the Writer never inspects the elements) or =fence:= absent / nil / not a well-formed token (=field= "fence", "keys", "seq", "last_line_sha256", "generation", "ref") | =field= |
| =append_failed= (fenced) | a persist stage (write / sync / receipt) fails on the FIRST fenced append; the Writer is warm-failed | =stage= only - the seam reason is NOT echoed (unlike the legacy =append/2= reply, which keeps its =detail= unchanged); later calls answer =writer_failed= (SG-M2) |
| =snapshot_foreign= | a well-formed token this Writer did not mint (other Writer, forged ref, other generation, mutated field) | none |
| =snapshot_stale= | a minted token whose head was superseded | =expected_seq=, =current_seq= |
Append precedence (S-M4): option validation (=fence_invalid=) -> token authentication (=snapshot_foreign=) -> head
check (=snapshot_stale=) -> event validation (existing clauses) -> persist. A refused fenced append leaves the
journal bytes, the head receipt bytes AND the mutating Fs trace unchanged; an unfenced valid append still works
after it. =fence: nil= is =fence_invalid=, never a silent unfenced append.
