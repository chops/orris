#+title: Command executor migration (caller migration over the foreground foundation)
#+PROPERTY: status delivered contract

* Implementation status
Delivered. =AiOrchestrator.Run.Executor= implements =AiOrchestrator.Commands.Executor= for =start= / =resume= /
=cancel= (verb scope, stamp revalidation, context validation, input-hash binding, the =restart_empty= selector) and
delegates to =AiOrchestrator.Run.Executor.Owner=, the owned foreground harness that starts =Run.Supervisor=, makes
the single =:retry_only= second attempt on =journal_exists=, awaits the Server, closes the Writer on success and
runs the teardown protocol (=lib/ai_orchestrator/run/executor.ex=, =run/executor/owner.ex=).
=AiOrchestrator.Run.Server= admits the command under the Writer lock through the durable-prefix decision table
(=acceptance_ambiguous=, =journal_exists= for =:retry_only= / =:restart_empty=, =command_run_mismatch=,
=idempotency_conflict=, replay, =command_superseded=, =:continue=) with =Commands.Idempotency.compare/2= as the pure
comparison. The bounded continuation ships as =Host.open(:continue, ...)= + =Reducer.continue/5=
(=lib/ai_orchestrator/lifecycle/host.ex=, =lifecycle/core/reducer.ex=); lease-prefix recovery ships in the
reducer's =ensure_lease_prerequisites= / =lease_ownership_coherent= with the closed =lease_ownership_ambiguous=
rejection. The CLI enters every lifecycle verb through =Commands.invoke/4= with =Run.Executor=
(=lib/ai_orchestrator/cli.ex=; =RunFSM= remains as an internal seam with no production caller). Rows E-*, C-*, L-*
and D-* live in =test/run/command_executor_red_test.exs=; the operator-path and restart-empty CLI rows in
=test/cli/cli_test.exs=. Not delivered: any other verb, a long-lived shared multi-run host, a run registry/monitor or daemon shape,
automatic restart, responsive status/cancel/timers from the executor, new events or schema fields, and actor
authentication (the CLI actor is the operator class with its existing id source). The existing application root
(=Application.children/0=, which mounts the =Journal.Ownership= arbiter) and the CLI's explicit restart-empty
selector (=lib/ai_orchestrator/cli.ex=) do ship and are what this executor runs under.

* What this unit is, and is not
ONE =Commands.Executor= implementation, =AiOrchestrator.Run.Executor=, that makes the caller-migration rule true for
the CLI: every public lifecycle command enters through =Commands.invoke/4= and executes inside the sole
Writer-owned run transaction, which is the integrated foreground subtree (=Run.Supervisor= -> Writer ->
=Run.Server= -> Work.Supervisor). The executor is the foreground OWNER of that subtree for one command: it starts
it, awaits the Server, tears it down (bounded), and returns the Host result shape. Verbs in scope: =start=,
=resume=, =cancel= only. Valid-but-out-of-scope verbs are rejected before any Writer, file or effect activity;
future verbs stay deferred.

* Decisions
- (a) The executor was specified as an interface first and implemented in reviewed units (below).
- (b) The CLI keeps reading spec/plan (and hashing the exact consumed bytes) as before and passes them as INTERNAL
  EXECUTOR CONTEXT, never as command arguments. =command.run_id= is bound to the executor identity: for =start= it
  is the id the CLI allocated through the Id seam and the run is opened with exactly that id; for
  =resume=/=cancel= it must equal the run id folded from the LOCKED accepted prefix (=Writer.opened/1= lines)
  before any effect, else the closed rejection =command_run_mismatch=. =start='s argument hashes must equal the
  consumed spec/plan hashes (existing sha256-of-bytes semantics; the values the reducer journals as =spec_hash= /
  =plan_hash=), else =command_inputs_mismatch=. A pre-lock Reader load is preflight only.
- (c) =run_server_down= surfaces to invoke callers as-is; Writer/Reader rejection clauses and the structured CLI
  output are preserved; no redundant wrapper.
- (d) =RunFSM= keeps its signatures as an internal compatibility/test seam, is documented as NOT a supported
  public lifecycle surface, has no production caller after the migration, and no =prior_lines= arity is silently
  rebound.
- Admission lives in =Run.Server= under the owned Writer (lifetime, not CPU location, is what keeps it inside the
  lock); Host/Effects keep receipt/commit/effect machinery; =Commands.Idempotency= is the pure comparison.
- The consumed spec/plan are bound to the accepted =start= through its =args_hash= (rule 4 of =execute/2= makes the
  retry's args equal the consumed hashes; the comparison then equates them with the accepted stamp) even when
  =plan_recorded= does not exist yet; additionally =run_created.data.spec_hash= must equal the context
  =spec_hash= on continuation.
- No =replayed= field on results.
- Delivery units: (A) the owned foreground executor + admission (verb scope, stamp revalidation, context, run-id
  binding, second-attempt start admission, lifetime) with NO production CLI change; (B) stamping,
  retry/continuation and the CLI caller migration as one fully gated unit; then (C) bounded continuation, (L)
  lease-prefix recovery, (D) explicit restart-empty admission. Each row below is labelled with its unit.

* Interface (exact; internal executor context, not a command surface)

=Run.Supervisor= config gains =open: :create | :existing= (default from mode: :run -> :create, otherwise
:existing); the Writer child receives =create: open == :create=. Baseline (pinned as a control): a =:run= on an
existing journal is rejected by the Writer's exclusive create BEFORE any Server exists, so a same-id start retry
can only be admitted through the second attempt above.

=Run.Supervisor= config gains one optional key, =command: Contract.Command.t() | nil=, and an =admission= key
(=:fresh | :retry_only | :restart_empty=, validated against =open=, the command and the mode). With a command
present, =Run.Server= performs, in =:opening= after discovery and BEFORE =Host.open=, using only
=Writer.opened/1= (the verified, repaired, locked view), the decision below.

* Durable-prefix decision table
Over the LOCKED verified prefix P (=Writer.opened/1= lines) and the command C, in this order; every arm that does
not execute leaves the journal bytes unchanged and performs no effect:

| # | condition | decision |
|---+-----------+----------|
| 0 | admission :restart_empty and P has any accepted line | the Writer's =journal_exists= (unit D; whatever the preflight saw) |
| 1 | rows = acceptance events in P whose =data.requested_by.command_id= == C.command_id; more than one | ={:error, %{clause: "acceptance_ambiguous"}}= (never =Enum.find=) |
| 2 | zero rows, admission :fresh (a :create that succeeded) or :restart_empty over a verified-EMPTY prefix | EXECUTE: open with =run_id = C.run_id= (start) - the stamp goes on the ONE acceptance event the ADR maps (start->run_created, resume->run_resumed, cancel->run_cancel_requested) IF the reducer emits it, reasons faithful to args, =command.now= not journaled |
| 3 | zero rows, admission :retry_only (start's second attempt) | the Writer's =journal_exists= preserved (empty existing journal; legacy without a stamp; any other command's journal) |
| 4 | zero rows, resume/cancel | run id of P must equal C.run_id else =command_run_mismatch=; then EXECUTE as row 2. | 10 | match, A incomplete, P terminal (a cancel whose run ended otherwise) | =command_superseded= (fail closed; nothing invented) |

COMPLETE(A) is a durable-prefix predicate over A's OWN INTERVAL: the events of P strictly after A and strictly
before the next LIFECYCLE ACCEPTANCE EVENT after A, if any. A lifecycle acceptance event is identified by its EVENT
TYPE - =run_created=, =run_resumed=, =run_cancel_requested= (the actor-aware command ADR's mapping) - independently
of whether its attribution is a structured stamp, absent, or the read-side legacy literal: the accepted journal
contract keeps =requested_by= optional and the unchanged Host emits unstamped =run_resumed= /
=run_cancel_requested=. An UNSTAMPED acceptance is therefore a boundary but never a matchable identity: retry
matching still requires the unique valid structured stamp (row 1 counts stamped rows only; no identity is inferred
for an unstamped acceptance), and an older incomplete stamped command cannot consume a later unstamped command's
terminal as its own - =command_superseded= stays the fail-closed result. No new stamp is required on historical
records. Evidence outside that interval is never A's: a terminal or blocking boundary reached by a LATER command
does not retroactively complete an earlier incomplete command, and a terminal already present before A is not A's
consequence. Never "run_started exists" (the reducer emits =run_started= BEFORE the work it starts; an interrupted
dispatch prefix already contains it).
- start / resume: A's interval contains a terminal - =run_completed=, =run_failed=, =run_cancelled= or
  =run_budget_exhausted= (the Fold's full terminal vocabulary, =terminal?=) - or ends in a blocking attention
  (fold status "blocked" at the interval's end); then A is complete and REPLAY returns the CURRENT verified fold
  (which a later command may have moved on), =appended_events: []=.
- cancel: =run_cancelled= inside A's interval.
- A complete before a later acceptance stays complete (row 7); an incomplete A followed by a later acceptance
  stays superseded (row 8) even if that later command terminates the run.
Pinned sub-cases (each its own row): cut after =run_started= before any dispatch -> continue (one =run_started=);
cut after =assignment_dispatch_sent= -> continue with re-observation (one dispatch, one adapter delivery); cut
after =gate_started= -> continue through the existing gate recovery (a =ReconcileGate= effect precedes any new gate
attempt); a later acceptance (a resume accepted after an interrupted start) -> the start retry is
=command_superseded= while the resume retry continues; a run blocked on attention -> the start retry REPLAYS the
blocked result; =run_cancel_requested= without =run_cancelled= -> continue with exactly one =run_cancelled=;
completion BEFORE a later acceptance (a start blocked on attention, then a cancel accepted and completed) -> the
start retry replays (current fold: cancelled) and the cancel retry replays; a later acceptance BEFORE completion
(a start interrupted after =run_started=, then a cancel accepted) -> the start retry is =command_superseded=;
=run_budget_exhausted= is a terminal (fresh resume/cancel on it are no-ops). No boundary the journal cannot prove
is called complete; no new completion event exists.

* Lifetime and teardown
The subtree's lifetime is the executor's: an OWNED foreground harness process (trapping exits; the supervisor's
linked parent; monitoring the caller; itself MONITORED, never linked, by the caller) starts the subtree, awaits the
Server to completion (no timeout) through an asynchronous request so that its caller-death monitor stays responsive
while work is held, then runs the TEARDOWN PROTOCOL over every owned identity (supervisor, Writer, Server, Work): a
bounded orderly =Supervisor.stop=, then a direct kill of each still-live owned process joined under a bound; a
survivor is reported as =run_executor_teardown_incomplete=, never as success, and root death is never taken as
subtree closure. Every trappable failure of the owner's own work (barrier raise/throw/exit or an invalid barrier
result included) runs under one closed boundary: teardown first with the latest known identities, then the caller
receives =%{clause: "run_executor_down", kind, class, digest}= (the contract's closed result class and digest; no
reason or stack bytes, in the reply, the DOWN reason or the logs), and the owner exits =:normal=. The owner replies
through a fresh reference only after the protocol completed, and the caller waits for the owner's own completion
before returning. The caller's =trap_exit= flag is never changed; no message of the caller's is consumed; the
caller receives no EXIT signal from the executor. Caller death -> the owner stops the subtree (Port close ->
guardian EOF) and exits; no terminal is fabricated. There is NO wait-timeout: the foundation's =Run.Server.await=
timeout semantics are unchanged and a responsive timed-return invocation is a later explicit API/lifetime design,
not silently named abandonment. A second invoke on a locked run directory receives the Writer's own rejection
(=second_live_writer= from the in-BEAM Ownership arbiter; =run_locked= across OS processes).

Writer close visibility: the CLI contract surfaces a failed close after a successful run (=journal_close_failed=,
status 70, summary still on stdout). The owner therefore closes the Writer explicitly after a finished command,
before the orderly stop, and reports a failed close as =close: {:error, rejection}= on the result; an error result
keeps its primary error and goes straight to the orderly stop + reap.

Worker handoff (from the effect-owner unit): the owner acknowledges the Server's ={:run_worker_registered, ref,
worker, server}= BEFORE its =:subtree_started= barrier and extends its facts with =worker=; the barrier contract is
TOTAL: a barrier is called with exactly the two names =:handoff_received= and =:subtree_started= and must answer
=:ok= to both; every fault, a missing clause included, is an owner failure under the closed boundary.

* Test harness rules the rows depend on
Every test tracks owner, supervisor, children and callers it learns of and reaps them itself in cleanup with fresh
monitors (bounded kill + DOWN), because the defect under test is exactly a leaked owner or subtree; no test relies
on the executor's own cleanup to clean up after a failed assertion, and none drains the mailbox arbitrarily.
Registration precedes assertion: the executor's =trace= is a test-owned COLLECTOR process that registers every pid
it sees under the test's key before forwarding the message, so a partial start or a missing final notification
still leaves the already-started pids reaped. The collector is an extra asynchronous hop, so no assertion assumes
delivery at zero timeout across it; a test either awaits the named trace set with a bounded receive or first asks
the collector to FLUSH (a marker the collector answers only after every message queued before it has been
registered and forwarded). Teardown is a protocol, not a snapshot: reap the owned producers/callers known so far,
flush the collector so every identity they published before dying is registered, reap the newly registered pids,
repeat until the set is closed, then stop the collector, and only then remove the temporary directories. The
executor emits ={:run_executor_started, owner, sup}= before it calls the test barrier, so the barrier ack is the
acknowledged registration point where a test needs one. Crash positions are invocation-relative: a FaultFs receipt
ordinal counts that adapter's own receipt publications, and every crash fixture asserts the durable signal, prefix
length, last type and command id before any retry is classified. Activity witnesses use =FaultFs.trace/1= and are
proven by positive and negative baseline controls that never touch the executor.

* Findings surfaced during unit B (measured, not accommodated; each resolved by a later unit)
- CONTINUE arm (decision-table row 9): the reducer's only continuation path was =resume_execution=, which ALWAYS
  emits =run_resumed= (a lifecycle acceptance event) before continuing, and its cancel path (=cancel_execution=)
  always emits =run_cancel_requested= before the releases; the Fold tracks no pending-cancel state. So "continue
  with no second acceptance event" could not be produced by the existing machinery: a continued start would
  journal an unstamped =run_resumed= that, by the event-type rule, ends the start's own interval and supersedes it
  on the next retry; a continued cancel would journal a second =run_cancel_requested=. Unit B therefore failed the
  continue arm CLOSED with =%{clause: "command_continuation_unsupported"}= (bytes unchanged, no effect) until unit
  C (below) gave the reducer a stamp-less continuation mode that emits no acceptance event. The alternatives
  rejected: an unstamped =run_resumed= that is NOT an interval boundary (contradicts the event-type rule); a
  continuation =run_resumed= carrying the SAME stamp (contradicts "one acceptance event per command"); a new
  event type (schema change).
- Empty-journal restart (CLI): =run --resume= on a journal killed before its first event (an existing EMPTY
  events.jsonl) used to restart the run by opening the existing file and appending a fresh run. Under the table a
  start is =:create= (the Writer's exclusive create refuses an existing file) and the only second attempt is
  =retry_only=, whose zero-match rule keeps =journal_exists=. Resolved by unit D: a distinct admission the CLI may
  REQUEST when it observes an empty journal in preflight (the lock, not the preflight, is the authority); preflight
  deletion and dropping the behaviour were rejected.
- CLI test corrections (disclosed): "unexpected runtime exception still releases roster claims" expected the
  adapter's RuntimeError to propagate through the CLI process; under the executor the exception is closed inside
  the owned subtree (=run_server_down=, status 70, no adapter bytes) and the claims are still released - the test
  asserts that. The E-5 "cancelled meanwhile" fixture interrupted right after =run_created=; a cancel there is a
  =preamble_violation= (the journal requires the preamble first), so the interruption is placed after
  =run_started=.

* Unit C - bounded internal CONTINUATION
Purpose: the decision table's CONTINUE arm (row 9) for an accepted-but-incomplete command that is the LAST
acceptance of a nonterminal prefix, without a second acceptance event. Selected ONLY by =Run.Server= admission
from the current Writer-verified accepted/repaired prefix after the unique stamp + arguments comparison and the
last-incomplete/nonterminal classification. No public verb, no new event or schema field, no weakened
acceptance-type boundary, one acceptance row per command.

Host/Core boundary (pinned):

#   -> {:ok, Host.Loop.t()} | {:error, map()}

#           (run_spec_loaded, plan_recorded, run_started - whichever are absent), then the existing

#   resume: the existing recovery from the accepted run_resumed's position, WITHOUT a new run_resumed.
#   cancel: the pending cancel is DERIVED from the admitted run_cancel_requested (last acceptance, no

* Unit L - lease-prefix recovery
Purpose: a durable prefix cut INSIDE an assignment's lease preamble (after =assignment_requested=,
=pane_lease_requested=, =pane_lease_acquired=, =workspace_lease_requested= or =workspace_lease_acquired=) must be
recovered lawfully by BOTH the existing recovery (plain =Host.resume=) and the internal continuation. Measured
before the fix (imported as L-0): a =pane_lease_requested= cut let the recovery DELIVER once and persist
=assignment_dispatch_sent= with no =pane_lease_acquired=; the durable journal then failed =Fold= with
=dispatch_without_pane_lease= and every further retry failed closed. That was a semantically invalid durable
prefix written after an adapter delivery, not merely a failure to complete.

Interface (no schema, no new public verb, no daemon scope): in =continue_resumed= / =resume_open_assignment=, the
lease prerequisites of an open assignment are DERIVED from the verified prefix (the Fold assignment's
pane/workspace lease flags and the pending =pane_lease_requests= / =workspace_lease_requests= rows) and only the
MISSING lawful prerequisites are appended, in order, BEFORE any prompt projection or dispatch: a pending pane
request is completed by =pane_lease_acquired= under its own =lease_request_id= (a request+acquire pair only when
no request exists), the workspace lease likewise under its =workspace_lease_id=. Existing identities (assignment
id, request ids, workspace lease id) are reused; one command acceptance; the interrupted delivery is re-observed,
never re-sent. If the verified prefix cannot determine lawful ownership (no pane_ref / claim for a pending
request), the recovery refuses or raises attention BEFORE any dispatch: no ownership fact is invented.
Cancellation releases only what was acquired and never invents an acquisition to release it. Invariant: EVERY
durable prefix of the recovered journal folds valid.

Pins:
- Delivery-entry durability (L-3): the prerequisites must be DURABLE WHEN the adapter is entered, not merely
  ordered in the final result. Test double =PrefixCheckingDispatch= folds the durable prefix at deliver entry (the
  journal file on the executor path; a recording receipt sink on the plain path) and records whether the
  assignment's pane lease and role-required workspace lease were held; a guard control (L-G) shows it flags an
  early delivery. L-3 also counts adapter entries (an adapter call without a row cannot pass).
- Interrupted repair table (L-5): on the pre_dispatch resume seed the measured stale-repair suffix is 1
  run_resumed, 2 workspace release requested, 3 workspace released, 4 workspace reacquired, 5 pane release
  requested, 6 pane released, 7 pane reacquired, 8 projection, 9 dispatch; each of 2..7 is a cut with its identity
  asserted; the same command's retry completes with no extra acceptance, one delivery, pending release ids
  completed once under their own id, every release request completed exactly once (a lease the crashed instance
  had reacquired is stale again for the retry's instance - measured - so at most two stale-repair requests per
  lease across the two attempts), prefixes valid. L-6: a crash DURING the missing-prerequisite repair - the
  continuation's FIRST receipt must be the acquisition (never a projection/dispatch), the durable cut folds valid,
  the next retry completes once. L-4 covers a pending pane request AND a pending workspace request.
- Ambiguous ownership (L-7): two pending pane requests for one assignment naming different panes are ADMISSIBLE
  (Reader, Writer and Fold accept; fact imported from a review probe). Closed outcome pinned: the recovery REFUSES
  before any append or dispatch with the Host rejection =%{"reason" => "lease_ownership_ambiguous",
  "assignment_id" => id}= - no arbitrary candidate, no invented acquisition, no delivery. This is a pre-effect
  rejection on plain resume, executor resume and continuation: nothing is appended on any of those paths,
  including no new acceptance. The Host does not commit a reducer suffix discarded by a bare error; there is no
  special acceptance flush for this rejection. A single unambiguous pending request stays the positive (L-1/L-2).
- Identity reuse observable (L-8): Fold/Writer-accepted prefixes with NON-default ids (=plr_custom_7=,
  =wsl_custom_9=) require acquisitions under exactly those ids with the request's pane_ref / mode binding; EVERY
  acquisition in the journal must name a journaled request (no pre-filtering); held-lease checks correlate
  releases to the specific pane_ref / workspace_lease_id.
- Actual recovery context (L-9): the prerequisites are those of the assignment's ACTUAL recovery context - a
  reviewer's request row names its review, so its work item is the review item (kind review) and no workspace
  policy applies; the reviewer positive (interrupted at its dispatch, resumed plain and by continuation) appends
  no workspace request and completes.
- Durable identity only (L-10): identity is read from the DURABLE prefix only (this step's own emits never prove
  ownership): the uniquely proven held pair is the last durable acquisition whose request id is one of the
  assignment's requests AND whose pane is that request's pane, not undone by a release of that pane;
  =lease_ownership_coherent= runs BEFORE any repair or emit on both recovery entries and refuses (closed ambiguity
  rejection, nothing appended) when a held lease has no proven pair; the stale repair reacquires exactly the
  proven pair; the completion release names the held workspace lease, else the single journaled one. L-10: a held

* Unit D - explicit restart-empty admission
Purpose: preserve CLI =run --resume= on a journal killed before its first event (an existing EMPTY events.jsonl)
through a DISTINCT admission, not a relaxation of :fresh or :retry_only. The CLI preflight only REQUESTS it; the
locked Writer-verified accepted/repaired prefix is the authority.

command_context_invalid field restart_empty before any I/O); Run.Supervisor config =open: :existing, admission:
:restart_empty= with the command present (validated like :retry_only). Admission: the locked prefix must be
verified EMPTY (no accepted line, no receipt) -> execute the start with its stamp (one run_created), binding
run_lock_path/repair as usual; a NONEMPTY prefix at lock acquisition -> the Writer's =journal_exists= without
append or effect, even if the preflight saw it empty; a missing journal is not authority to recreate (the Writer's
own rejection, =journal_missing=); corrupt or locked prefixes keep their Writer rejections. No preflight deletion
or truncation; no retry from the explicit mode; ordinary start (:create -> journal_exists -> :retry_only) stays
byte-for-byte in policy (zero matches, the empty journal included, remain journal_exists).

Repaired authority (measured): a torn first unaccepted line (no receipt file) verifies to an EMPTY prefix with a
=truncate_tail= repair - the explicit admission FOLLOWS the verified prefix and admits the start (D-R1); receipt
absence is VERSION-SPECIFIC (measured both ways): a complete LEGACY v1 first line with no receipt file verifies

=advance_receipt= 0 -> 1 planned by the Reader and performed by the Writer (events.head written with seq 1 and the

directory proves the repair, the feature directory is left for the executor's own Writer to repair); a corrupt
receipt keeps the Writer's own rejection (D-R3). No Reader/Writer contract change. Ordinary Writer-authorized
tail/receipt repair may change unaccepted tail/receipt bytes; "bytes unchanged on refusal" is a statement about
accepted lines and about no command event being appended, not a ban on that repair.

admission control, not the race.
