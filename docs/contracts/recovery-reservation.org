#+title: Recovery reservation vocabulary
#+options: toc:nil
#+PROPERTY: status delivered contract

* Implementation status
Delivered as vocabulary only. =run_recovery_reserved= is a reserved, typed event: its version 1 schema is in
=lib/ai_orchestrator/journal/schemas/event_data.ex=, its reserved membership in =Journal.Event= and
=Journal.Vocabulary=, and the fold count with both refusal clauses in =lib/ai_orchestrator/journal/fold.ex=
(=Fold.State.recovery_reservations=). The fixture is =test/fixtures/contracts/journals/fold_recovery_reserved=
with the measured baseline =test/fixtures/contracts/journals/BASELINE-FOLD-PROJECTIONS.json=; the rows are
=test/journal/recovery_reservation_red_test.exs= (R-7/R-7b in =test/run/command_executor_red_test.exs=), and the
inventory pins in =test/contracts/event_vocabulary_test.exs= and =event_payload_schema_test.exs= carry the
after column of the transition table. No producer exists: nothing in =lib/= appends this type, and the Writer
refuses it reserved-first.

* Scope
ONE new reserved event type with its own schema, ONE integer Fold.State field, one new fixture directory. NO
producer (no acquisition writes it), no exhaustion terminal, no restart coordinator, no cleanup-unproven
refusal, no continuation, no runtime consumer of =restart_attempts= (the typed budget stays inert), no
deadline, no daemon topology. Omission at exhaustion stays not implemented: no injected default.

* The event
- Type =run_recovery_reserved=: a RESERVED member of the vocabulary (Journal.Event =@reserved_types= and
  Vocabulary =@reserved= with target classification =:w4=), NEVER an acceptance type (Server =@acceptance_types= unchanged) and
  NEVER a terminal type (Fold =run_terminal?/1= and Server =@terminal_types= unchanged). Reserved means: readable and
  fold-legal history with a typed schema, refused by =Event.validate_append= / the Writer with
  =reserved_event_type= (the existing reserved-first check). EXPORT (measured control C-3): the typed
  envelope export =Event.json_schema/0= follows TYPED CURRENT VERSIONS, not reserved membership - it already lists
  =run_budget_exhausted= and =run_failed= - so the new typed reserved type is INCLUDED there while
  =Event.validate_append= / the Writer still refuse it reserved-first; no separate "read export" exists and none is
  claimed. Direct =EventData.parse(_, :append)= admits the current version (structural only); the refusal is Event's.
  Its version history is its own, starting at 1 (=EventData.current_version("run_recovery_reserved") == 1=).
- EventData schema, version 1, REQUIRED fields only, unknown keys rejected:
  | field | domain (structural, field level) |
  | =attempt= | integer >= 1 |
  | =limit= | integer >= 0 |
  | =cause_class= | closed enum "writer_exit" \vert "writer_timeout" \vert "owner_down" (the three causes the delivered source emits: Run.Recovery's closed reasons and the Server's =run_effect_owner_down= clause; no other value in v1) |
  | =lost_generation= | integer in the lock-generation domain 1..999999999999 (the =run.lock.N= filename grammar; never a pid) |
  | =authority= | closed enum "executor" \vert "host" |
  Integers only: booleans, floats (1.0 included), strings and null are =invalid_event_data= with the field named;
  newline-bearing or canary strings in any field are refused without echo (errors carry field names, never values).
- CHECK LOCATIONS AND PRECEDENCE (explicit): (1) envelope + structural field domains = EventData (read and append
  modes alike, =invalid_event_data=); (2) cross-field: a reservation with =limit 0= or =attempt > limit= is
  structurally well-formed but SEMANTICALLY impossible (nothing could be reserved) - refused by the FOLD with clause
  =recovery_reservation_invalid= (=at_seq=, =field "attempt"=), not by the schema, so a line stays readable as bytes;
  (3) history: the Fold requires =attempt == recovery_reservations + 1= (=recovery_reservation_out_of_order=,
  =at_seq=, =expected=) - the count is RUN-WIDE and never resets across =lost_generation=, =authority= or command
  acceptances; =lost_generation= values need not be adjacent or unique (lock releases also advance generations) and
  no sequencing of them is enforced. Envelope/structural refusals precede fold refusals; preamble/terminal refusals
  (existing) precede the reservation checks.
- Fold placement (existing rules, measured): a reservation is legal only in phase =:run_started= (after
  =run_started= / =run_resumed=) and before a terminal; before =run_started= it is =preamble_violation=; after a
  terminal it is =events_after_terminal= (it is not a cleanup event). While BLOCKED (open attention) it is legal:
  it is not a dispatch type (=blocks_on_attention?= unchanged) and does not resolve attention.
- Fold effect: =Fold.State.recovery_reservations= (integer, initially 0) increments by one; phase, status, terminal?,
  reason, assignments, attention, leases, work items unchanged; =last_seq= and =event_ids= advance as for any event.
  No last-attempt/limit cache (the journal retains those fields; no consumer identified).
- Projections: =Fold.summary/1= and =RunSummary.render/1= carry NO new field and render byte-identically for a
  journal with reservations versus the same journal without them, EXCEPT the sequence truth (=last_seq=) which
  advances; behavioural fields (status, run_id, completed ids, attention) are unchanged.
- Command classification (Server =classify/3=): a reservation between an accepted command and its retry is NOT an
  acceptance boundary and not a terminal: the accepted command's interval, stamp comparison and =:continue= admission
  are unchanged; the second-acceptance refusal is unchanged.

* Comparators
=historical_projection/1= = the full canonical Fold.State with only the pending field removed (event_ids RETAINED) - used against the baseline file (C-4, R-8). =comparison_projection/1= = the same minus event_ids - used only for the reservation-added versus stripped-and-renumbered comparison (R-6), where event ids necessarily differ.

* Fixture selection
Tests select reservation lines by DECODED type (=event["type"] == "run_recovery_reserved"=), never by substring, so formatting can not decide whether a reservation exists.

* Cause vocabulary provenance
=writer_exit= and =writer_timeout= are Run.Recovery's closed reasons; =owner_down= is NORMALIZED from the Server's =run_effect_owner_down= clause - there is no producer in this unit and no cause value is claimed to be a literal emitted string.

* Public-state shape statement
=Fold.State= gains exactly one field, =recovery_reservations= (default 0). Literal old-struct equality therefore
changes; the rows prove BEHAVIOURAL projection equality: for every historical fixture journal, folding with the
new field REMOVED equals the fold at baseline. Historical fixture bytes are unchanged; the new fixture lives in
its own directory.

* Pinned inventory changes (a recorded inventory change, not a silent test edit)
declared 53 -> 54; reserved 20 -> 21 (=run_recovery_reserved= at :w4); typed 44 -> 45 (evidence-backed reserved
grows by one: the new fixture is its evidence); reserved-untyped stays 9; produced stays 33.
