#+TITLE: Delivery deadline (deliver/reconcile under the Worker fence): source mapping, baselines, decision table
#+PROPERTY: status delivered contract

* Implementation status
Delivered. =Contract.Effect.Dispatch= and =Contract.Effect.ReconcileSend= carry =deadline_unix=; the reducer threads
the durable assignment deadline into both from the continuation and takes an attention-only branch
(=journal_deadline_attention/3=) for the stable reasons =dispatch_deadline_exceeded= / =dispatch_reconcile_timeout=
(=lib/ai_orchestrator/lifecycle/core/reducer.ex=); =AiOrchestrator.Effects= honours =:adapter_runner= for both
effects through =deliver_through/3= and answers =DispatchFailed= / =SendReconcileFailed= from the owner's retained
intent on =:expired= (=lib/ai_orchestrator/effects.ex=); =AiOrchestrator.Run.Worker= fences =Dispatch= /
=ReconcileSend= through =execute_fenced/4=, refuses a missing or malformed deadline closed
(=admit_deadline!/1=, =dispatch_deadline_missing=) and reports fence facts per operation kind
(=lib/ai_orchestrator/run/worker.ex=, =Run.DeadlineFence=). Baselines DC-1..DC-16 live in
=test/run/delivery_deadline_baseline_test.exs=, rows D-*/DP-*/DA-*/DO-*/DL-* in
=test/run/delivery_deadline_red_test.exs=, and the imported kind-attribution probes with their two companions in
=test/run/delivery_deadline_review_probe_test.exs=. Not delivered (outside this unit): attention resolution for a
deadline attention, retry expansion, deadline renewal, a new settle protocol, daemon changes.

* Scope
Deliver (=Effect.Dispatch=) and reconcile (=Effect.ReconcileSend=) under the Worker's existing one-shot fence:
source-clause mapping, MEASURED baseline controls, a closed decision table, the minimal product delta and the
rows that pin it. The label "delivery deadline" is provisional (typed budgets name the wider concept).

* Source facts before this unit

  =[:assignment_id, :command]=. NEITHER carried =deadline_unix= (pinned DC-5); only =Observe=, =Timer=,
  =PrepareGate= and =AwaitGate= did.

  =assignment_observation_started=) and travels in the reducer continuation or queued struct, never in the Worker
  effect. =dispatch_effect= is the single =Dispatch= constructor; =converge_queued_send/2= the single
  =ReconcileSend= constructor. Sites and deadline availability are in the enumeration below.

  =[SendReconciled, SendReconcileFailed]=. =Observation.TimedOut= is admissible for =Observe= only and the reducer's
  =unwrap= hardcodes =observation_timeout=: reusing it for delivery was rejected.
- =Journal.Vocabulary.@reserved= has NO =delivery_unknown= / =dispatch_timeout= type. No new vocabulary, event or
  observation class is introduced.
- Existing typed failure paths: =assignment_dispatched(..., {:error, reason})= -> =journal_blocked_assignment= with
  =dispatch_failure_reason= (=put_new= reason "dispatch_failed", detector "dispatch_failed", pane_state
  "unknown"), =ret(:blocked)=, EXCEPT =*_invalid_return= -> =ret({:error, reason})=; =dispatch_recorded(...,
  {:error, ...})= same route; =queued_send_retried(..., {:error, ...})= same route; =queued_send_reconciled(...,
  {:error, reason})= -> =queued_send_blocked(..., "dispatch_reconcile_failed", "unknown")= with a FIXED map that

  an unknown delivery and is not reused for expiry.
- =journal_blocked_assignment= emits =agent_wedge_detected= (=agent_wedge_detected_data=: agent_ref, pane_ref,
  assignment_id, detector, =stale_for_ms= defaulting to 200000, =pane_state= defaulting to "blocked",

  attention_id, reason, blocking_entity, summary_path, summary_hash, resume_command, optional =detail= only for

  DC-2 full payloads). Precedent for attention WITHOUT a wedge: =journal_prompt_failure= (attention only, a stable
  reason string, assignment binding).
- Effects ran the deliver/reconcile adapter IN the calling process (the Worker) with no runner seam and no fence;
  only =Observe= honoured =:adapter_runner= (DC-4).
- =LocalPane.deliver= (daemon-first dispatch): =proven= -> =reconcile(message_id, payload_hash)= -> =absent= is the
  ONLY case that sends; =delivered= / =queued= reconstruct the receipt (=send_status "reconciled"/"queued", replayed
  true=) with ZERO send; =ambiguous= / =conflict= refuse (=dispatch_reconcile_<outcome>=); =absent= at the daemon's
  =@max_delivery_attempts= (2) refuses =dispatch_attempts_exhausted= (adapter-internal bound); a reconcile fault
  ({:error, map}) propagates as the deliver's error. The message id is the deterministic =snd_<hash>= idempotency
  key; the payload identity is the prompt's =SensitiveBytes.hash=, which equals the journaled
  =assignment_prompt_projected.prompt_hash= (DC-9).

Admission policy (delivered; no unfenced-nil fallback anywhere):
- After propagation every production constructor above carries an integer =deadline_unix=; the fresh-no-receipt
  resume site threads =recorded_deadline_unix=.
- The Worker REFUSES a =Dispatch= / =ReconcileSend= whose =deadline_unix= is not a non-negative integer with a CLOSED
  =effect_failed= (kind =:error=, class/digest of the clause atom =dispatch_deadline_missing=, runtime settled, no
  adapter entry): nil, a struct, a string, a float or a negative value never disable the fence (rows DA-1..DA-4).
- Legacy no-receipt resume of a journal WITHOUT =deadline_unix= on =assignment_requested= therefore REFUSES closed
  at the Worker (pinned explicitly; no silent renewal, no unfenced fallback); it is not covered by the
  recorded-deadline fallback, which only runs after a queued receipt. Whether such journals exist in the corpus is
  a separate finding (none in the scenario fixtures: every =assignment_requested= carries a deadline).
- The ONLY unfenced path is the direct owner-local =Effects.execute= WITHOUT a runner (the Host oracle, legacy
  direct callers): the pre-unit behaviour exactly, witnessed by DC-4 and the control DA-control.

* Decision table
Cases: (i) already due BEFORE adapter GO at the Worker dequeue; (ii) a deliver INTERRUPTED after GO (delivery
UNKNOWN: the task's DOWN proves nothing about external settlement); (iii) a reconciliation query that TIMES OUT (no
answer; no inference of delivered/absent from a missing answer).
| case | decision (existing observation classes, attention-only reducer branch) | consequence the old routes would have given (rejected) |
|------+------------------------------------------------------------------------+---------------------------------------------------------|
| (i) deliver already due | Effects answers =DispatchFailed{reason: %{"reason" => "dispatch_deadline_exceeded", "detector" => "dispatch_deadline"}}= from the OWNER's retained intent when the runner says =:expired= (no adapter entry, no send); the reducer's dispatch error routes recognise the stable reason and take the ATTENTION-ONLY branch below | the unchanged route would emit a wedge with synthetic =stale_for_ms 200000 / pending_count 0= that measured nothing: rejected |
| (ii) deliver interrupted after GO | the same =DispatchFailed= shape; the journal COMMITS attention (attention-only, reason =dispatch_deadline_exceeded=, blocking_entity = assignment); the run is =blocked=; a later resume is REFUSED until the attention is resolved (DC-8); when an operator resumes after resolution the fresh-no-receipt path re-presents the SAME message id and asks the daemon (DC-9/DC-10 prove a landed/queued ACK yields ZERO second send, DC-11/12/13 prove no absence is manufactured) | pre-attention crash (DC-7 shape, no attention) and committed attention (DC-8 refusal) are DIFFERENT states and are kept distinct |

* Attention-only reducer delta (delivered)
- Two stable reason strings (engineering interface, not policy): ="dispatch_deadline_exceeded"= (the fresh,
  recorded and retry dispatch routes) and ="dispatch_reconcile_timeout"= (the reconcile route).
- One private helper mirroring =journal_prompt_failure=: =journal_deadline_attention(state, assignment_id, reason)=
  = =human_attention_required_data(next_id("att", n), assignment_id, %{"reason" => reason})=, emit ONLY
  =human_attention_required=, bump =next_attention=, =ret(:blocked)=. No =agent_wedge_detected= (no synthetic pane
  facts), no =detail= (the durable deadline already lives on =assignment_requested=; no duplicate field, no schema
  change), no new terminal, no free-form map extension.
- Per-route payload matrix: fresh =assignment_dispatched=, recorded =dispatch_recorded=, retry
  =queued_send_retried=: reason == "dispatch_deadline_exceeded" -> helper; every other reason -> UNCHANGED
  (=journal_blocked_assignment= with =dispatch_failure_reason=, byte-identical events, DC-1 pins them). Reconcile
  =queued_send_reconciled=: reason == "dispatch_reconcile_timeout" -> helper; every other reason -> UNCHANGED
  (=queued_send_blocked= fixed map, DC-2 pins it). Invalid-return precedence unchanged.
- Emitted fields for the timeout branch: exactly =human_attention_required{attention_id, reason, blocking_entity,
  summary_path, summary_hash, resume_command}= (the existing builder, no new key).
- Fold / continuation consequence: identical to any attention (=open_attention_ids= gains the id; resume refused
  until resolved, DC-8); no retry, no attempt closure, no resend: the next operator resume re-enters the
  fresh-no-receipt path (the daemon's answer decides).
- Gap recorded: no existing supported operator command resolves an assignment-attention of this kind, so D-6
  cannot witness "resume after resolution" without inventing a resolution; the row stops at the refusal. No new
  operator policy or producer is part of this unit.

* Product delta (delivered)
1. =Contract.Effect.Dispatch= / =ReconcileSend= gain =deadline_unix= (=integer() | nil= in the type; the enforce
   keys are unchanged so legacy direct callers compile; the Worker refuses nil closed).
2. Reducer: =dispatch_effect/3= carries the deadline purely from the continuation at the four sites (fresh;
   recorded/resume =ensure_dispatch_sent= via =recorded_deadline_unix=; queued/proven-absent retry from
   =queued.deadline_unix=; =converge_queued_send= into =ReconcileSend=); the attention-only branch is taken ONLY
   when =reason["reason"]= is =dispatch_deadline_exceeded= or =dispatch_reconcile_timeout= on the four error routes
   (=assignment_dispatched=, =dispatch_recorded=, =queued_send_retried=, =queued_send_reconciled=); invalid-return
   precedence and every other reason are byte-identical (DC-1/DC-2 pin them). No Worker journal read, no fresh

3. Effects: =Dispatch= / =ReconcileSend= honour =:adapter_runner= through =deliver_through/3= with the Observe
   grammar; the closure captures only the dispatch module, the command and the dispatch options; =:expired=
   answers the EXISTING =DispatchFailed= / =SendReconcileFailed= from the owner's retained intent with the stable

4. Worker: the Observe execute path is generalised (=execute_fenced/4=) to =Dispatch= / =ReconcileSend=;
   =admit_deadline!/1= refuses a non-integer or negative deadline closed (=:erlang.error(:dispatch_deadline_missing)=

5. Fact attribution by kind (test-only seam): fence facts carry =kind:= (the intent struct); the observer seam

   own kind at emission on every path. The default keeps the Observe fact stream byte-identical (the Observe rows

   Dispatch's) while the delivery tests opt in (=[Effect.Dispatch, Effect.ReconcileSend, Effect.Observe]=). Holds

   =kind:=, and a retired op's stale wake (idle owner, nested receive, held point) reports THAT op's kind read from
   the retired map; an unknown (foreign) wake at the idle owner carries =kind: nil= and is reported unfiltered; a
   foreign wake inside a live op is attributed to the live op (its kind, its filter). Timer/identity grammar
   unchanged.

* Boundary rules
- A genuine timeout uses the EXPIRED retained deadline and an operator resume never renews it; committed attention
  refuses through the existing API (D-6a, DC-8); a pre-attention crash with a STILL-LIVE retained deadline enters
  the daemon-first reconcile path (DC-7, DC-9..DC-13); a pre-attention crash with an EXPIRED retained deadline
  follows strict D1 at the resume: zero adapter entry, attention-only (D-6c); task DOWN is never external
  settlement; retained Port cleanup follows the existing owner lifetime and one =:settle= (D-4p); expiry is not a
  new settle protocol.
- Fresh and queued attempt bounds stay separate and unchanged; no resend from uncertainty (DC-9..DC-13), no new
  attempt closure, elapsed time never becomes absence; the original attempt's daemon-side state survives the
  caller's death (DC-9: the authority still holds attempt 1 after the loss).
- Every timed row uses the COHERENT real =SystemClock= for unix and monotonic (DO-2, D-4, D-4p, D-4r, D-5i, D-6c)
  and proves the due instant on that clock; a FixedClock monotonic counter is never armed against real timers.
  Short real-deadline rows WITNESS future-or-now at the =:armed= fact on the same clock (the arm's OWN =unix_now=
  read, not a later sample) and GO (=task_started= / adapter entry) before expiry; the durable deadline is never
  renewed.
- D-3i pins the one legitimate prior =SnapshotArtifact= call (it precedes =assignment_prompt_projected=) as exactly
  =[{:snapshot, "as_0001"}]= and then ZERO deliver / reconcile / observe entries for the due assignment; no change
  to snapshot ordering.
- D-6c saves the first config, carries the SAME =prompt_root= into the resume, binds the original assignment /
  message key / deadline and proves the retained prompt file is reachable BEFORE any expiry claim; the
  missing-prompt negative stays DC-7b, never as expiry evidence.
