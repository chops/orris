** Implementation status
:PROPERTIES:
:CUSTOM_ID: implementation-status
:END:
~AiOrchestrator.Dispatch.PaneClient~ (~lib/ai_orchestrator/dispatch/pane_client.ex~)
consumes the v1 reply shapes below: a reply without an explicit ~protocol_version~ is
read as a v1 reply, and a send that names no message id passes the decoded v1 reply
through unchanged. The fixtures and ~CONTRACT_HASH~ under
~test/fixtures/contracts/ipc/v1/~ are pinned by
~test/dispatch/pane_client_contract_test.exs~, which also checks that this document
names every ~pane_status.state~ and ~queue_reason~ value. The daemon that produces
these frames (ai-pair) is a separate project; this repository ships only the consumer.

This document describes the ai-pair IPC v1 contract as consumed by ai-orchestrator. The
fixtures in ~test/fixtures/contracts/ipc/v1/~ are the daemon reply shapes this
repository pins; it does not add fields to the wire.

** Framing and version
:PROPERTIES:
:CUSTOM_ID: framing-and-version
:END:
- Transport is a local Unix-domain socket using four-byte length-prefixed JSON
  frames.
- ~protocol_version~ is implicitly ~1~ and is absent from v1 requests and
  replies.
- A ~send~ request may carry ~msg_id~. The daemon uses it for delivery and
  telemetry correlation but does not echo it in a v1 reply.
- Strings of the form ~<name>~ in fixtures are dynamic placeholders. Tests must
  replace only documented dynamic fields before comparing decoded objects.
- ~pane_status.state~ is one of ~idle~, ~busy~, ~dialog~, ~dead~, or ~unknown~.
- ~pane_status.agent~ is a registered agent string or ~null~.
- ~pane_status.classifier~ is a classifier name string.
- ~pane_status.pending_count~ is a non-negative integer; the fixture's ~0~ is a
  representative value, not a fixed constant.
- A queued send has ~queue_reason~ equal to ~debounce~, ~busy~, ~dialog~, or
  ~unknown~.

** Reply fixtures
:PROPERTIES:
:CUSTOM_ID: reply-fixtures
:END:
| Fixture                                  | Meaning                                                                                    |
|------------------------------------------+--------------------------------------------------------------------------------------------|
| ~ping.ok.json~                           | Daemon is reachable; ~<version>~ is the running ai-pair version.                           |
| ~pane_status.ok.json~                    | Pane is registered; ~<pane_id>~, ~<state>~, ~<agent>~, and ~<classifier>~ are dynamic.     |
| ~pane_status.error.missing_pane_id.json~ | Request omitted a usable pane ID.                                                          |
| ~pane_status.error.pane_not_found.json~  | No live registered state machine owns the pane ID.                                         |
| ~pane_status.error.pane_dead.json~       | The pane owner died between lookup and status observation.                                 |
| ~send.sent.json~                         | Text was pasted synchronously.                                                             |
| ~send.queued.json~                       | Text entered the live pane state machine's bounded in-memory queue but was not pasted yet. |
| ~send.error.missing_pane_id.json~        | Request omitted a usable pane ID.                                                          |
| ~send.error.pane_not_found.json~         | No live registered state machine owns the pane ID.                                         |
| ~send.error.queue_full.json~             | The bounded pending-send queue is at its v1 cap of 32.                                     |
| ~send.error.missing_text.json~           | Request omitted a string payload.                                                          |
| ~send.error.oversize.json~               | Payload exceeds the v1 cap of 524288 bytes.                                                |
| ~send.error.pane_dead.json~              | The registered pane state machine is terminal.                                             |
| ~send.error.send_timeout.json~           | The pane state machine missed the configured call deadline; ~<detail>~ is diagnostic text. |
| ~send.error.paste_failed.json~           | Synchronous tmux paste failed; ~<detail>~ is diagnostic text and is not machine-readable.  |

~queued~ and ~queue_full~ are typed outcomes, not transport failures. Consumers
must preserve the distinction. A later revision defines consumer behavior for each
outcome (see ~ipc-v2.org~).

Malformed JSON and unknown commands are framing/command-dispatch errors outside
this consumer fixture set. They remain daemon behavior but are not pane-delivery
outcomes.

** Hash
:PROPERTIES:
:CUSTOM_ID: hash
:END:
This repository pins the JSON files and ~CONTRACT_HASH~ under
~test/fixtures/contracts/ipc/v1/~. The hash is lowercase SHA-256 over this byte
sequence:

1. Select only ~*.json~ files in this directory.
2. Sort their relative filenames by byte value.
3. For each file, append ~filename~, one NUL byte, exact file bytes, and one NUL
   byte.
4. Hash the concatenation and store the 64 hexadecimal characters plus a final
   newline in ~CONTRACT_HASH~.

The documentation file and ~CONTRACT_HASH~ itself are not hash inputs.

** Planned protocol version 2 changes
:PROPERTIES:
:CUSTOM_ID: planned-protocol-version-2-changes
:END:
The following are targets, not v1 facts: explicit ~protocol_version~, capability
advertisement, ~msg_id~ echo, subscription, and incompatible-peer rejection.
They require a contract revision and fixtures before implementation; protocol
version 2 (~ipc-v2.org~) specifies all of these except subscription.
