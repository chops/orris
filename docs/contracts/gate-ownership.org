* Premise
The journaled gate =timeout_s= IS enforced by =Gate.Execution.await= (bounded receive =min(remaining_ms,
@receive_cap_ms)=; the cap is a maximum, not the wait) and by the guardian backstop =--timeout-ms=; a timeout maps
to =GateFailed= (settled, proof gone) or =GateUnsettled=. The gap this document addressed was OWNERSHIP /
RESPONSIVENESS: =AwaitGate= ran on the Worker's generic synchronous clause, so the owner could not serve
status/settle while a gate was awaited, and a Server timer could not interrupt it. Direction chosen: the live gate
deadline is owned by a Server-side timer authority; the Worker stays an event-driven owner. Task-wrapping
=gate_mod.await= at the deadline or at deadline+grace was rejected.

* Binding constraints (G-N1..G-N4)
- G-N1 :: =Effects.gate_await= reads =Runtime.handle=; =Execution.await= / =next_record= receive the Port's records
  in the CALLER; termination/released-at state lives in the process dictionary keyed by Port. The Worker owns all
  of it. Task-wrapping the await loses owner mailbox and memo access before any expiry. Runtime/Port/memo must not
  cross processes casually; NO generic =adapter_runner= route for =AwaitGate=.
- G-N2 :: =Worker.fenced_run/await= and =held= are selective nested receives that do not serve status/settle. A
  fence or finite chunks alone do not meet the responsiveness criterion; a Server timer message cannot interrupt a
  synchronously blocked owner without an owner-resident event/protocol change. Demonstrate the real mailbox path,
  not an adapter double that removes the constraint.
- G-N3 :: do NOT import the assignment rule "already due at dequeue -> zero adapter calls". An =AwaitGate= may refer
  to an ALREADY PREPARED/RELEASED native process; it must avoid new work/release but may need expiry/cleanup calls
  on the retained handle. =Execution.not_expired= at prepare/release is a different stage. Pin separately:
  live-handle case, pre-GO case, queued terminal-record precedence. =await_records= consumes EXIT/DEAD before
  reading the clock and keeps doing so (an unconditional due refusal would discard real proof). No fabricated
  =GateUnsettled= fields, no =gate_failed= settled/gone claims; mapping only from measured proof.
- G-N4 :: =cap_ms= is a maximum timer chunk, NOT a grace duration; no deadline+grace policy. The execution deadline
  stays distinct from any proposed bounded cleanup/proof wait. The direction preserves the guardian backstop and
  the existing result mappings while identifying the authoritative live deadline owner. Worker hard-death proves
  nothing about external descendants.
- =timeout_s= 600 stays hard-coded in this unit; the configurability gap is stated, not silently removed.

* Resumable primitives on =Gate.Execution= (delivered; =await/2= and =expire/1= unchanged)
- =begin_await(running, opts) :: {:done, answer} | {:pending, waiting}= ; =answer= is the existing =await/2=
  grammar (={:exit, map} | {:timeout, map} | {:error, rejection}=). Semantics = the exact prefix of =await/2=:
  termination memo first; =next_record(port, 0)= consumes an already-queued EXIT/DEAD before any clock read;
  otherwise pending with no clock decision and no further receive. Caller MUST be the Port owner; any other
  caller: =ArgumentError= (contract violation), the owner's handle untouched.
- =resume_await(waiting, port_message) :: {:done, answer}= (resume never answers pending; a non-terminal record is
  the closed =await_failed= exactly as in =await/2=) ; =port_message= is ONE message the owner already dequeued:
  ={port, {:data, {:eol, line}}}= (parsed by the existing private parser: EXIT -> =exit_outcome=, DEAD ->
  =memo_dead= with the memo written in the calling owner), ={port, {:data, {:noeol, _}}}= and ={port,
  {:exit_status, _}}= before a terminal record -> ={:done, {:error, %{clause: "await_failed"}}}= closed (no raw
  bytes in the rejection). A message for a different Port: =ArgumentError=, never silently pending.
- Valid =waiting= value :: an opaque map =%{port, running, opts, ref}= created by =begin_await= in the owner; valid
  only in that process, only until its terminal answer (single consumer): resuming a consumed value raises
  =ArgumentError=; a =waiting= whose handle has since been expired answers ={:done, {:timeout, memo}}= (memo reuse,
  never a fresh run); a handle whose Port is closed answers ={:done, {:error, guardian_gone | await_failed}}=
  (existing clauses only).
- Owner-local bookkeeping: ONE process-dictionary entry ={Execution, port, :descriptor}= holding the active
  descriptor, reused by a duplicate =begin=, replaced by =:finalized= on any terminal answer (from =resume= or from
  a =begin= that consumed a queued terminal). Every activation carries a fresh =make_ref()= (internal lifetime
  bookkeeping, not a public attempt-generation API): the consumed old descriptor never matches a new one (stale), a
  fresh begin after a terminal error is a new distinct wait (fresh), a duplicate begin of the active wait returns
  the SAME stored descriptor (active-duplicate), and no fresh native GO/release occurs (same Port, release memo
  untouched). Memos stay where the baselines measured them. Nothing crosses a process.
- =begin_await= order: =owner!= (a Port alive and connected to ANOTHER pid raises =ArgumentError=; a closed Port
  is judged ONLY by this process's retained evidence - the release memo, a termination memo, or a descriptor; none
  -> =ArgumentError=, no permissive nil branch), memo first, then =next_record(port, 0)= (queued EXIT/DEAD finalised
  through the legacy path), then closed Port -> existing =guardian_gone=, else ={:pending, descriptor}=; NO clock
  read.
- =resume_await= order: exact Port (foreign Port raises), then =active!= (the caller's dictionary must hold THIS
  descriptor: a non-owner or a finalized descriptor raises), then memo (first valid resume after external expiry
  answers it and finalises), then decode (=:eol= through =parse_record=, =:noeol= -> =malformed=, =:exit_status=
  -> =exited N=), every answer finalising the descriptor.
- Blocking inside the primitives (disclosed) :: the zero-timeout scan in =begin_await=; the terminal finalisation
  in =resume_await= (=barrier(:after_exit)=, =drain_exit= up to 1000 ms, evidence hashing) and =memo_dead='s
  =drain_exit=; =expire/1= waits =wait_ms(opts) = settle_ms x rounds + 2000 ms margin= (test opts 200 x 2 + 2000 =
  2400 ms; defaults =@default_settle_ms 2000 x @default_rounds 2 + 2000 = 6000 ms=) THEN =drain_exit/1=.
  Everything else is the owner's own =handle_info= cadence. No claim of non-blocking finalisation follows from the
  primitives alone.
- Ownership retained :: the Port stays connected to the owner across begin/resume; memos stay ={Execution, port,
  *}= in the owner's dictionary; failure cleanup goes through the ORIGINAL =running= handle (=expire/1= /
  =abandon/1=), never through =waiting=.

answer, completion-vs-expiry decided by the Worker's single mailbox) was delivered with a refined grammar in

=settle_await/3= and =pending/1=; a third primitive =Execution.settle_await/1=; the Server's gen_statem generic
timeout driven through =Run.DeadlineFence= in chunks. Two design notes recorded here still hold: replacing
=Runtime.entry.handle= by a composite would break =abandon_one/2 -> executor.abandon(handle)= (the original opaque
handle stays in the entry; the resumable descriptor lives separately), and =Effects.execute= must not globally
return a pending value (the synchronous =Host.advance= and the Worker's synchronous boundary are unchanged
consumers; the opt-in is a separate entry point). Explicitly NOT part of either unit: an adapter task for
=AwaitGate=, =Port.connect=, process-dictionary relocation, a grace period (G-N4), a new observation or event
type, a change to =await/2= callers, a schema/fixture change.

* Constraints recorded by this document and their resolution
- C-1 :: the guardian record parser is entirely private (=defp=, module attributes); an owner-resident resumable
  wait cannot decode a dequeued Port record without a public =Execution= entry point or a duplicated grammar
  (forbidden). Resolved by =begin_await/2=, =resume_await/2= and =settle_await/1=.
- C-2 :: =gate-execution-wiring.org= pins "awaiting IS its work; nothing schedules elsewhere" for the Host; the
  Worker path now schedules the deadline in the Server. That sentence remains true of the Host path only.
- C-3 :: =Run.Server= had no timer machinery for a gate deadline; the Server-side authority was net-new (test
  double first, then the gen_statem generic timeout).
- C-4 :: the Worker's catch-all =handle_info/2= dropped a Port record; resolved by the retention Port clause
  (=gate-record-retention-proposal.org=) and, for the pending Port, by the resume clause. Record routing/retention
  begins at handle ownership (not at =:awaiting= registration), bound to the exact retained Port and gate/attempt
  lifecycle, retaining early EXIT/DEAD/exit_status (or their validated terminal state) in order until
  AwaitGate/cleanup consumes them; never an effect result for an op the Server has not issued; a dead/closed Port
  does not invalidate a terminal record already received; one-time finalisation and foreign-Port refusal
  preserved; no Port/memo transfer.
