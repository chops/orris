#+TITLE: Observational host registry: in-VM live-run lookup without admission changes
#+PROPERTY: status implemented in-VM slice (GREEN); rows in test/host/

* Implementation status
Implemented (in-VM slice): =lib/ai_orchestrator/host.ex= (=AiOrchestrator.Host=: =status/2=, =lookup_run_id/2=,
=collision/2=), =lib/ai_orchestrator/host/monitor.ex= (=Host.Monitor=) and =lib/ai_orchestrator/host/executor.ex=
(=Host.Executor=); the Application mounts =Host.Monitor= after =Journal.Ownership=. The rows in
=test/host/host_registry_red_test.exs= are the acceptance; =test/host/host_baseline_control_test.exs= pins the
oracles they compare against. Nothing under =lib/ai_orchestrator/run/= changed, admission is unchanged and
=Run= does not depend on =Host=. Delivered boundary deps are =[Run, Commands, Contract, Journal]= (Projection
and Config are not used by this slice). Not delivered here, by design: the CLI does not route through
=Host.Executor= yet (no runtime switch), no endpoint, no host-mounted run subtrees, no dependency change.
=collision/2= answers ={:ok, %{clause: "host_registry_unique", count}}= when at most one directory carries the id.

* Scope
One BEAM. A purpose-built observational monitor records which run directories are live under this VM's
run subtrees so an in-process caller can look them up. It changes nothing about command admission,
journal ownership or the per-run owner/reaper protocol. Another OS process (for example a separate CLI
invocation) cannot see this monitor; cross-process views belong to a later host endpoint.

* Boundary layout
A new boundary =AiOrchestrator.Host= sits ABOVE =AiOrchestrator.Run= with dependencies
=[Run, Commands, Contract, Journal]= and exports =[Executor, Monitor]=. The Application depends on =Host= (the
CLI will once it routes commands through =Host.Executor=); =Run= never depends on =Host=. Nothing under =lib/ai_orchestrator/run/= changes.

* Interface
- =AiOrchestrator.Host.Monitor= :: a GenServer; the Application starts one named instance after
  =Journal.Ownership=, and =start_link(name: name | nil)= starts injectable instances for tests. State:
  =by_dir= (canonical run directory -> identity record, unique) and =by_id= (run id -> list of identity
  records, non-unique) plus a process monitor on each registered owner. Identity record (complete, all keys
  required): =%{run_dir, run_id, owner, supervisor, server, writer, worker, generation}=; =register/2= and
  =unregister/2= take =(monitor, record)= and are asynchronous (=GenServer.cast=), so they never block or fail
  the caller. Stale-cleanup protection: an entry is keyed by directory and carries its owner pid and
  generation; a DOWN or =unregister= that names an owner or generation other than the current entry's leaves
  the entry untouched (a late old-owner DOWN never erases the replacement), and a registration whose owner is
  already dead is dropped on the immediate DOWN and never persists. No client can remove another owner's entry.
- =AiOrchestrator.Host.Executor= :: implements =Commands.Executor= by delegating to
  =AiOrchestrator.Run.Executor.execute/2= with a composed barrier: for the label =:subtree_started= it first
  registers the owned identities (a cast wrapped in try/catch so every raise, throw or exit collapses to =:ok=),
  then calls the user's barrier exactly once with the identical label and map and returns the user barrier's
  value unchanged (=:ok= or not), propagating any raise, throw or exit unchanged so the owner's closed
  =run_executor_down= semantics are untouched. Other labels pass straight through. After
  =Run.Executor.execute/2= returns, the caller-side =unregister/2= cast is likewise guarded. The command
  result, the journal bytes and the observed cleanup are byte-for-byte what =Run.Executor= produces for the
  same inputs. In-VM seam: the executor context key =:host_monitor= (pid or registered name, default the
  Application instance) selects the monitor and is stripped before delegation; it is not a command argument.
- =AiOrchestrator.Host.status/2= :: =status(run_dir, opts)= consults the monitor with a bounded call
  (=monitor:= pid or name, default the Application instance; =ownership:= the =Journal.Ownership= server
  consulted, default the Application arbiter; =timeout:= a positive integer of ms, default 1_000, the
  TOTAL budget for the monitor lookup plus the ownership lookup; any other =timeout= value answers
  ={:error, %{clause: "host_status_timeout_invalid"}}=) and then =Journal.Ownership.status/2= with the
  remainder of that same budget. Answers: ={:ok, %{registered: true, live: true,
  generation, owner, supervisor, server, writer, worker}}= when an entry exists and =Ownership= confirms the
  same generation and =:live=; ={:ok, %{registered: false}}= when no entry exists — an UNKNOWN, carrying no
  =live= key, never a claim that no run is live (R7); ={:ok, %{clause: "host_registry_inconsistent",
  generation}}= when the entry's generation disagrees with =Ownership= (the entry is then ignored for
  everything else); ={:error, %{clause: "host_monitor_unavailable"}}= when the monitor is absent, crashed,
  renamed or does not answer within the budget; ={:error, %{clause: "host_ownership_unavailable"}}= when the
  monitor answered but the ownership lookup does not answer within what remains of the budget. The whole
  operation returns within =timeout= plus scheduler slack; it never blocks the caller beyond it. =lookup_run_id/2= returns
  every entry for a run id (a diagnostic list, never an admission input); =collision/2= reports
  ={:ok, %{clause: "host_registry_collision", count}}= when more than one directory carries the id.
- Diagnostics are closed maps naming only clause and generation: no run directory bytes, tokens, lock paths,
  pids of other runs or reason terms.

* Rules
- R4 Hint only. Admission stays with the existing authorities: =second_live_writer= (same BEAM),
  =run_locked= (another OS process or a stranded lock), =journal_exists= then the single =retry_only= attempt
  for a stamped start, and the durable-prefix decision table. Registry presence authorizes nothing; registry
  absence proves nothing. Same-run-id/different-directory collisions are diagnosed, never acted on.
- R5 One monitor process; registration runs in the owner (the barrier), cleanup runs on the owner's DOWN and
  from the caller after return; no Elixir Registry with mixed key kinds.
- R6 Fail-soft. A missing, crashed, stalled or renamed monitor never changes the command result, the journal
  bytes or the teardown; the user barrier keeps its ordering (=:handoff_received= then =:subtree_started=),
  single invocation per label, return value and escape semantics (a raising barrier is still the owner's closed
  =run_executor_down=).
- R7 Orderly close versus stranded lock. On an orderly =Writer.close/1= the Writer releases the disk lock and
  retires the arbiter record; a later acquisition proceeds under ordinary journal admission. A lock is
  stranded only when the arbiter's registration is lost AND the Writer died before releasing; then the next
  acquisition fails closed with =run_locked= until the tree re-registers or an operator adjudicates.

* Rows
Baseline controls (=host_baseline_control_test.exs=, must pass now; raw =Writer=/=Ownership= rows, never
counted as host feature rows): B-1 second live writer refused with generation; B-2 orderly close then
reacquire; B-3 stranded lock after arbiter loss -> =run_locked=; B-4/B-4b owner barrier order, identities,
return required, raising barrier -> =run_executor_down=; B-5 =Ownership.status= is the live-run authority.
RED (=host_registry_red_test.exs=; the guard fails on the missing interface, the bodies exercise real held
commands so a no-op stub is rejected): H-1 a held run is registered with exact identities and the same
generation =Ownership= reports, and the entry is gone after completion and owner DOWN (absence carries no
=live= key); H-1b delayed registration for a dead owner never persists; H-1d stale DOWN/unregister from an
older owner never erases the replacement; H-2 duplicate start/resume/cancel against a HELD live run through
=Host.Executor= produce exactly the =Run.Executor= results, journal bytes and generation unchanged; H-2b
absence proves nothing; H-5 two HELD concurrent runs under one monitor: two entries, exact identities,
collision diagnosed; H-7 complete record with a disagreeing generation -> inconsistent, matching generation ->
live; H-6a/H-6d absent and stalled monitors: result term, journal bytes and the per-label FULL barrier payload
(the test reads the run tree from the TRUSTED traced supervisor while the owner is blocked and requires the
payload to equal the exact role -> pid map, same key set, same pid per role: a swap of two live pids is a
corrupted payload) identical to =Run.Executor=, every owned process's DOWN joined after the command, status
bounded by the requested budget with the 1_000 ms default and timeout validity pinned; H-6e ONE total budget: a
monitor leg that consumes a measured ~700 ms of a 1_000 ms budget (test-owned forwarding proxy in front of
the monitor; the monitor answers ordinary GenServer calls, so such a proxy is a valid monitor) followed by a
stalled ownership lookup closes with =host_ownership_unavailable= within 1_000 ms plus <= 200 ms slack, which
a fresh-timeout-per-leg implementation cannot meet; responsive control live; the global arbiter untouched; H-6b/H-6c non-=:ok= return, raise, throw and
exit of the user barrier: identical result, identical journal bytes and identical invocation sequence
(exactly one =:handoff_received= call, the escape ends the run) on both routes; H-9a the monitor proven registered then killed (DOWN joined) mid-run: the run
completes; H-9c the Server killed mid-run: closed =run_server_down= unchanged and the entry removed on the
owner's DOWN.

* Non-goals
Cross-process views, endpoint, admission changes, restart policy, host-owned teardown, projection index.
The next slice mounts host-owned run trees under a host supervisor while preserving the owner/reaper protocol.
