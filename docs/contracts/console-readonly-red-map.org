* Review F1-F6 resolution (RED rev3)

  a change_mode of the path to exactly 0600 after it, and a 32-byte write to D; any delete/rename/other mode/
  non-exclusive open/write_file of the path between the open and that write is a replacement. Mutants beside the
  faithful control: write_first, no_exclusive_open, chmod_then_replace, secret_elsewhere (H-10, each at its step).
  OTP's file API has no permission option on open, so the mode change is required, never a tuple match.

  reading replacement at the cut point; the oracle names that admission (H-11). The ack witness traces

  read-before-ack worker mutant fails (H-12); ten early controller kills leave no worker/read. Controllers are capped

* Test corrections made during GREEN (each an observation fix, never a weakened acceptance)
- C1-03a absent and duplicate Host: the HTTP/1.1 parser refuses them with 400 before the guard can answer 403; the
  cells accept either status and still require that nothing reaches the framework.
- C1-03f sibling-path navigation: the framework emits no dispatch telemetry for an unmatched path; the witness is the
  404 status (the guard only ever answers 403) with no socket connect.
- C1-11b: the admission window closes at the view's own server-side applied-read witness; the idle assertion is a
  bounded wait (the periodic refresh may have a read in flight at the instant of the assertion).
- C1-14: the browser is pointed at the loopback address itself ("localhost" resolves to ::1 first in the browser);
  page text is read after the connected view applied its read; the login/logout submits wait for their own
  navigations to land; the navigation diagnostic reports the page the browser ended on.
- Test boundary: outgoing references are not checked in test support; rows run with `--no-start` and the core is
  started by the test helper (its Host monitor answers real facts).
- Test-only dependency: `lazy_html` (Phoenix.LiveViewTest's HTML parser), never in the release.
