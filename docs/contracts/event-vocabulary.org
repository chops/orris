#+TITLE: Journal event vocabulary

The source vocabulary is =lib/ai_orchestrator/journal/vocabulary.ex=, checked
against declared event types, runtime emit sites and fixture journals by
=test/contracts/event_vocabulary_test.exs=.

This source snapshot declares54types:33produced and21reserved. Produced means a
runtime emit site exists; it does not certify the complete surrounding product
feature. Reserved means current production code cannot append that type.
Historical fixtures containing reserved types can remain fold-legal.

The production emit source for the33produced rows is
=lib/ai_orchestrator/lifecycle/core/reducer.ex=. The native vocabulary retains
historical producer labels and target-wave metadata; those labels are not a
second runtime owner or a promise of release dates.

* Schema and append boundaries
Payload-schema availability and append permission are separate checks. Twelve
reserved types have payload schemas without production producers:

- =assignment_failed=
- =context_patch_accepted=
- =context_patch_proposed=
- =contract_change_proposed=
- =contract_change_ratified=
- =notification_failed=
- =notification_requested=
- =notification_sent=
- =run_budget_exhausted=
- =run_failed=
- =run_recovery_reserved=
- =stop_policy_evaluated=

The remaining nine reserved types have no payload schema:

- =context_conflict_detected=
- =context_patch_rejected=
- =contract_change_rejected=
- =pane_lease_failed=
- =run_pause_requested=
- =run_paused=
- =scheduler_stalled=
- =work_item_failed=
- =workspace_lease_failed=

Reading one of those nine types fails closed with =event_schema_unavailable=.
Appending any reserved type fails earlier with =reserved_event_type=.

The exact payload schemas live in
=lib/ai_orchestrator/journal/schemas/event_data.ex=. Promoting a reserved type
requires its producer, typed payload, fold handling and positive/negative controls
in the same reviewed change, with this table updated.

For read compatibility, the only historical string accepted for =requested_by=
is exactly =operator=. New appends require the structured actor shape and bind
every string value to valid UTF-8 of at most4,096bytes. Historical reads remain
unchanged. The exported JSON Schema describes the structural version-2 append
envelope but does not encode this runtime byte bound.
