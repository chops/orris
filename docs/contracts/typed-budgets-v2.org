* Implementation status
Delivered. =AiOrchestrator.Spec.Budgets= (=lib/ai_orchestrator/spec/budgets.ex=, =validate/1=) is the
standalone strict schema, and =AiOrchestrator.Spec.RunSpec= (=lib/ai_orchestrator/spec/run_spec.ex=) accepts
=schema_version= 2 and answers =budgets/1= as specified below. The rows are
=test/spec/typed_budgets_red_test.exs= (B-0..B-3, V-1a..V-1d, V-2..V-9); the 25 =test/fixtures/**/spec.json=
files of control V-1d are all version 1 or negatives, none is version 2. No runtime consumer of a typed
budget ships with this contract: the typed map is read by =Run.Recovery.Exhaustion= only as a pure
calculation input, and no restart loop, migration command, or deadline actuator that consumes these typed budgets exists (the
delivered Worker and Server deadline fences act on effect and gate deadlines, not on typed budget values).

* Scope
Schema + accessor only: no event, Fold, reservation or exhaustion producer, runtime default, stop-policy
change, restart loop, deadline actuator, command re-acceptance, daemon topology, or migration COMMAND (its
absence is explicit, below). The immutability of run-spec v1 is the controlling fact.

* The controlling fact: run-spec v1 is immutable (controls V-1)
=AiOrchestrator.Spec.RunSpec.validate/1= keeps its version 1 branch unchanged (version 2 is validated separately and
strictly, as specified below); in v1 =budgets= is REQUIRED (absent ->
=invalid_run_spec_shape=) and is an UNTYPED map: arbitrary keys and values are accepted. Every ACCEPTED historical fixture
spec is v1 with =budgets {max_wall_clock_s, max_attempts_default}= (the corpus also holds negatives: an array-shaped
journal fixture and a version-99 fixture). Replacing that map with a strict schema would
change v1 admission and therefore the hash-bound meaning of every journaled =run_spec_loaded=; it is NOT a doc-only
versioning statement. v1 validation, input bytes, hashes and legacy behaviour stay byte-for-byte unchanged.

* The chosen bounded API
- =AiOrchestrator.Spec.Budgets= (Spec boundary) - a STANDALONE strict schema:
  =validate(term) :: {:ok, typed} | {:error, %{clause: "budget_invalid", field, reason}}=
  Fields (all OPTIONAL, integers): =max_attempts_default >= 1=, =restart_attempts >= 0= (0 VALID: one generation),
  =max_wall_clock_s >= 1= (the fixture spelling), =gate_attempts >= 1=. Omission of a field = NOT CONFIGURED:
  the typed map carries only the fields the input names; NO default is ever injected. Closed =reason= values:
  "unknown_key" (any other key; =field "budgets"=), "null" (a known field's explicit JSON null), "not_integer"
  (float, string, boolean, list, map), "below_minimum" (an integer under the bound). A section that is not a map,
  including JSON null, yields =reason "not_map"=, =field "budgets"=. Unknown keys precede known-field violations;
  known fields are checked in the order
  max_attempts_default, restart_attempts, max_wall_clock_s, gate_attempts; the FIRST violation is reported.
  UNKNOWN KEYS: an unknown key is arbitrary user content, never a diagnostic vocabulary - the refusal
  is EXACTLY =%{clause: "budget_invalid", field: "budgets", reason: "unknown_key"}=, never the key, its value or
  an inspect of either; keys of any type (binary, atom, integer, tuple) are judged without coercion and no atom is
  ever created from input; =field= names only the four literal field strings or "budgets". Integral floats (1.0)
  and map values are =not_integer=.
- =RunSpec.validate/1= gains =schema_version 2= as a separately supported version: the v1 shape with exactly two
  differences - =budgets= is OPTIONAL, and when present it must satisfy =Spec.Budgets= (a violation is the
  =budget_invalid= refusal above, NOT =invalid_run_spec_shape=). Everything else (gates, agents, allowed_roots,
  stop_policy, unrecognized keys) is validated exactly as v1. Unsupported versions (3, "1", "2", 1.0, nil, absent)
  are refused exactly as before (=unsupported_schema_version= for 3 / "1" / "2" / 1.0 / 2.0 / nil,
  =invalid_run_spec_shape= when missing; measured controls that EXCLUDE 2). THE TRANSITION, stated: version 2 was
  refused at the baseline and is ADMITTED by the delivered code; row V-2 is that transition's witness and no
  control asserts 2 refused. A v2 spec whose =budgets= is PRESENT but null / not a map reaches the standalone refusal through
  RunSpec (=field "budgets"=, reason "not_map" in every case), identically through the accessor. The ="null"=
  reason applies only to a known field inside a budget map, never the section itself.
  Precedence in v2: schema_version -> gates -> agents -> allowed_roots -> budgets -> shape (the existing v1 order
  with budgets inserted before the Zoi shape parse).
- =RunSpec.budgets/1= (accessor; precondition: a map returned by =validate/1= - it authenticates nothing about a
  run directory): ={:typed, typed}= for a v2 spec (={:typed, %{}}= when the
  section is absent), ={:legacy, map}= for a v1 spec - a v1 map is NEVER called typed, even when its contents would
  satisfy =Spec.Budgets= (no silent upcast). The fallback promise is LIMITED to unsupported or missing versions and
  non-map input -> ={:error, %{clause: "unsupported_schema_version"}}=. An UNVALIDATED map carrying version 2 has
  its =budgets= section judged by =Spec.Budgets= (a malformed section is =budget_invalid=, never typed); an
  unvalidated map carrying version 1 whose =budgets= is not a map is =invalid_run_spec_shape=, never legacy.
- No migration: a v1 run directory is never rewritten, upcast or reinterpreted; adopting typed
  budgets means authoring a v2 spec for a NEW run. There is no migration command in this unit, deliberately.
