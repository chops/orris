* Implementation status
This document is a test-only spike: its mechanism lives in =test/run/adapter_interruption_spike_test.exs=
(test-local =SpikeOwner=, allocation authority and harness) and nothing in it is a product module. The
production counterparts it argued for ship separately: =AiOrchestrator.Effects= accepts an =:adapter_runner=
seam (=lib/ai_orchestrator/effects.ex=, =lib/ai_orchestrator/effects/adapter_runner.ex=) for Observe, Dispatch
and ReconcileSend; =AiOrchestrator.Run.Worker= starts a linked =Task.Supervisor=, runs those three effects in a
task under a =Run.DeadlineFence= armed at dequeue, brutally kills the task at the due fence and answers that normal expiry as an
=effect_result= carrying the closed expired observation (=TimedOut= for Observe, =DispatchFailed= for Dispatch,
=SendReconcileFailed= for ReconcileSend; =lib/ai_orchestrator/effects.ex=), while a trappable adapter fault or
malformed adapter behaviour answers a closed =effect_failed= (=lib/ai_orchestrator/run/worker.ex=); =AiOrchestrator.Run.Server= arms the fence for =AwaitGate=
and actuates the owner (=lib/ai_orchestrator/run/server.ex=). Their contracts are =observe-deadline.org=,
=delivery-deadline.org= and =gate-async-await-proposal.org=; this spike's measurements are evidence for that
design, not the specification of the shipped modules.

* Mechanism under test (revision 2)
=SpikeOwner= (test-local GenServer shaped like the Worker's protocol, no =trap_exit=) owns, for the whole test:
a NONEMPTY =Effects.Runtime= (one =:prepared= entry whose handle is a LABELLED FAKE carrying the owner's Port; it
is an ownership witness, not a real =Execution= handle or gate proof), a real owner-opened Port (=/bin/cat=)
and a process-local sentinel. In =init/1= it starts a =Task.Supervisor= LINKED to itself (the candidate lifetime
mechanism; the production supervision tree is untouched and its approval is not implied).

** Runner boundary (AM-M1)
Every adapter runs INSIDE a task-side runner: the task first waits for the owner's GO token, then evaluates the
adapter under =try/catch=; a raw =raise= / =throw= / =exit= from ANY adapter is closed inside the task as
={:closed_failure, kind, Diagnostic.describe(reason)}= (existing closed vocabulary, digest only) before OTP could
log a Task crash; a normal value is returned as ={:ok, value}=. Fake adapters fail RAW (no self-catching). Death
reasons are recorded as a CLOSED class (=:normal= / =:killed= / =:shutdown=, anything else =:other=): no adapter
atom is transferred as if it were vocabulary.

** Admission and handshake (AM-M2)
ONE operation in flight: =start_op= is refused with =operation_outstanding= while the current operation is not
death-proven (its independent monitor DOWN not yet observed); no implicit interruption or resend. Admission
order: allocate the task (=async_nolink=, which owns =Task.ref= as monitor and reply tag), install the
independent death monitor, register the operation with a sequence number, THEN send the GO token; the adapter
never runs before its owner can observe it, so an immediate completion cannot race the monitor. Every fact is
tagged with the operation's sequence; =op_started= and every death fact carry the logical identity's =Task.ref=,
task pid and death ref. Facts arriving on a retired =Task.ref= or death ref are recorded as =old_task_fact= with
the OLD sequence and change nothing; a second message on the CURRENT =Task.ref= after its reply is recorded as
=duplicate_reply= and classified =duplicate_completion= by the fence.

** Facts and decisions
Facts are dequeued by the GenServer loop (no nested selective receive; the only bounded inner receive is a Port
round-trip inside a call). FENCE and RESULT facts go through =Run.DeadlineFence.observe/2=; admission, death,
old-fact, settle-shaped and unknown-message facts are recorded without it.
- reply dequeued first -> =observe {:result}= -> =:completed= / =:retain_result=; a later fence on the closed op
  is =ignored_fence :closed_op=.
- due fence dequeued first (from a REAL owner-armed monotonic timer with the owner-read clock and the retained
  canonical fence, or a hand-sent wake in ordering cases; arming inputs captured from ONE =unix_now= read) ->
  =:timeout_selected= / =:request_expiration= -> ONE kill request -> =Task.shutdown(:brutal_kill)= -> the return
  recorded as its own fact: ={:ok, reply}= -> =observe {:result}= -> =:completed_after_timeout= /
  =:retain_late_result= (timeout stays the winner, never settlement); =nil= -> harness-local
  =delivery: :unknown=; ={:exit, class}= -> the task had already died.
- early wake -> =next/2= re-arms the timer, no kill; duplicate fence while open -> stale, no second kill.
Kill REQUEST, shutdown RETURN, observed DEATH (closed class from the independent monitor, with all three
references) and result PRESENCE are separate recorded facts; =:killed= is never forced on a task that exited
normally.

** OS descendants (AM-M3, AM-M5, AM-M6)
An OS child is allocated by an ALLOCATION AUTHORITY, a test-tracked process started BEFORE any allocation, that
owns the child's Port (the requesting task's death never loses it) and writes the record into
=:persistent_term= at every transition: =:not_started= (written at registration) -> =:allocating= (written
BEFORE =Port.open=) -> ={:identified, pid, start}= or ={:allocated_unidentified, reason}= -> =:proven_absent=.
The oracle for the record is pushed into the ordered harness (=OwnedHarness.os_oracle!=, after BEAM reaping,
before directory removal) at registration; it answers =true= ONLY for the explicit =:not_started= or
=:proven_absent= states; a MISSING record, =:allocating=, an unidentified allocation or an unknown reap all stay
=false= (fail-closed: evidence retained, records erased only after proven closure). Seams: a =before_identity=
barrier after =Port.open= and before identity capture (the requester can be killed there; the authority still
captures the identity late), and =identity_failure= (a late identity-capture failure records the allocation as
unidentified). Negative controls use bounded helpers (seconds, not minutes) so nothing is orphaned beyond its
own lifetime.
OS probes return STRUCTURED outcomes ={:ok, out}= / ={:exit, code, out}= / =:timeout= / ={:raised, class}=,
each under a 2 s bound (a raise inside the command is caught inside the probe task; killing the probe task
after the bound is NOT a claim that the external command closed). Liveness combines two probes: =kill -0= gives
=:alive_signal=, =:esrch= (the kernel's "No such process": positively established absence) or =:unknown=
(permission, usage, timeout, raise); =ps -o lstart= gives =:same= / =:different= / =:empty= / =:unknown=.
=:alive= = signal + same identity; =:absent= = ESRCH, or the pid now carries a different identity; everything
else =:unknown=. COMMAND FAILURE IS NEVER ABSENCE. A command-runner seam lets a control inject each failure class
while a REAL tracked child is alive. Cleanup kills only =:alive=, joins to =:absent= under a bound, and returns
=:unknown= otherwise.

** Early observation (AM-M7)
The owner reports each early wake to a registered observer AT handling time with the state and kill count as
they are at that instant (={:early_observed, seq, state, kills, wait_ms}=); the test asserts on those captured
values, and a deliberately delayed observer that reads only after the due wake killed still sees every early
observation carrying =:running= and zero kills.

* Final-revision corrections (applied after review)
- The =:proven_absent= previously written after a sleep was INVENTED evidence and is deleted. Authority-owned
  Ports are opened with =:exit_status=; the authority stores the OBSERVED exit as ={:exited, pid, status}= /
  ={:exited_unidentified, status}= and only that proof (or an identity-bound reap) admits absence.
- Two S-4 topologies are kept and labelled: TASK-OWNED Port (the original measurement: the task marks
  =:allocating= with the authority before =Port.open=, opens the Port itself, reports pid + start identity to
  the authority, then blocks; after the task kill the child measurably survives) and AUTHORITY-OWNED Port (a
  different topology; exit-proof capable). Neither is described as the other.
- The requester-kill seam is a two-way acknowledged barrier (the authority reports =:allocating= and waits,
  without timeout, for the test's proceed token); the requester is tracked and joined (DOWN observed).
- Eligibility table corrected: =Effect.Timer= is an owner-side sleep, not =dispatch.observe=; only
  =Effect.Observe= carries =deadline_unix=; =Dispatch= / =ReconcileSend= do not.

* Measured results (reproduced by the shipped test)
- S-4 external descendant after task =:brutal_kill=: MEASURED =:alive= in BOTH topologies (task-owned Port and
  authority-owned Port); identity-bound cleanup then joined it to =:absent=.
  Limitation stands: BEAM task death proves only that task's death; it never contains an OS process tree.
- S-0 semantics measured as documented: =shutdown(:brutal_kill)= returned =nil= on a blocked task and consumed
  its monitor DOWN (the independent monitor reported =:killed=), ={:ok, reply}= on an arrived-but-undequeued
  reply, ={:exit, :normal}= on an already-exited task.
- S-1: the owner's Port I/O round-trip succeeded before and after the interruption; runtime entry, sentinel and
  =Port.info(:connected)= unchanged; the real timer produced early chunks before the due wake.
- S-2 (c): with the owner suspended, the fence wake queued first and the runner's ={:ok, {:ok, :delivered}}=
  reply queued behind it, =shutdown= returned ={:ok, reply}=; final state =:completed_after_timeout= with
  =:retain_late_result=, the kill request recorded, and the independent death reason =:normal=.
- S-2 (d): two early observations captured AT handling with =:running= and zero kills, then the due wake killed;
  the delayed observer read the same captured values after the kill.
- S-4 command-failure controls: permission, usage, timeout, raise, ps failure and empty identity each produced
  =:unknown= while the real child stayed alive; the requester killed after =Port.open= left the authority to
  capture the identity late and cleanup was proven; the late identity failure was recorded unidentified and the
  oracle refused.
- Both imported review probes pass (the raw throw is closed before Task crash logging; the
  second start is refused and the task supervisor keeps exactly one child).
- Harness findings disclosed: (1) a hand-sent fence must be armed in the OWNER's clock domain (revision 1's
  first draft armed at monotonic 0 and was perpetually early); (2) the owner is started UNLINKED from the test
  process; (3) revision 1's fakes caught their own failures and its =start_op= silently retired a running
  predecessor: both were harness defects, fixed by the runner boundary and the admission rule.

* API extension proposed by this spike (delivered later, outside the spike)
The spike proposed: an =adapter_runner= seam on =Effects= inputs (default in-process) supplied by the Worker for
deliver/observe/reconcile only; the Worker's own linked =Task.Supervisor=; a closed =effect_failed= reply for an
interrupted adapter with delivery unknown; and a deadline authority arming =Run.DeadlineFence= for the gate
await. The shipped source carries each of these (see "Implementation status"); the journaled form of a
delivery-unknown outcome remains a vocabulary decision outside this document. Ownership conflict named: any
adapter that must retain a Port, gate handle or memo across its call cannot run in the task; none does, and
gate work must not.
