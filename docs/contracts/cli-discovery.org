#+title: Explicit-root CLI journal discovery
#+date: 2026-09-10

* Operator entrypoint
=ai-orchestrator list --root <runs-root> [--json]= lists the direct run directories
under an explicitly selected root. =--json= may precede =--root=. Relative roots
are relative to the invocation's working directory; symlink/parent components
are resolved physically by the existing public Query boundary.

The default Org table shows directory reference, durable run id, recorded status,
last verified event sequence, whether repair is pending, and read errors. Recorded
status does not establish whether a process is running. JSON returns:
#+begin_src json
{"runs":[{"run_ref":"alpha","run_id":"run_example","status":"blocked","last_seq":12,"pending_repair":true,"error":null}],"skipped_outside_root":0}
#+end_src
Rows are sorted by directory reference. Different directories with the same
run id remain separate. A directory outside the physical root is skipped and
counted; non-directories are omitted. No global scan or configuration is inferred.

* Results and read semantics
Successful root discovery exits 0, even when individual rows cannot be read.
A failed row has null run_id, last_seq and pending_repair, status =invalid=,
and error =journal_missing=, =journal_empty=, =journal_invalid= or =run_unavailable=.
Unknown failures are sanitized; nested errors, filesystem paths, raw journal
payloads, context, projections and free-form failure reasons are not returned.

An explicitly missing root exits 74 with =runs_root_missing=; a directory that
cannot be listed returns =runs_root_unreadable=; unexpected failures return
=runs_root_unavailable=. These are JSON stderr reason maps, with empty stdout.
Missing/duplicate flags, unknown options and positional extras exit 64.
The existing =list=, =list --json= and directory-based status commands keep
their root choice and their results, including an empty implicit runs root.
Their output gained exactly one additive field, the pending repair the read
already observed; see "Pending repair in every read" below.

Query.list_runs chooses membership, then Query.run_summary supplies each row's
facts from one verified journal-prefix read. If that read fails after discovery,
the row is invalidated instead of retaining earlier status or identity. A torn
tail can therefore show its verified prefix with pending_repair=true. No repair,
receipt advancement, projection write, Writer, command or host observation runs.
Every invocation reads again; no process, ETS table or disk cache is retained.

JSON preserves valid Unicode directory references with Jason encoding. Org
encodes brackets, pipes, backslashes and control characters as visible hexadecimal
escapes so a directory name cannot insert an Org link, table column or terminal
control. Unsupported filename encodings produce a sanitized root error. Before
Query filters membership, a lossless =:file.list_dir_all/1= enumeration checks
every direct name; ordinary =File.ls/1= can silently omit raw names on Linux.
This check walks the configured root physically, preserving symlink/parent
components. It adds an observation, not an atomic filesystem snapshot.
Filename handling assumes Elixir's required UTF8 native filename mode; a VM
configured for Latin1 filenames is outside this qualification.
Enumeration failures retain Query's root-error classification; they cannot
produce a successful discovery result.

* Pending repair in every read
Every directory-based read reports the repair its verified load observed, as
=list --root= and =Query.run_summary= already did. =status --json= and
=replay --json= add a =pending_repair= object naming the action, the truncated
byte count and the receipt sequence before and after, and ONLY when one is
pending: a clean journal's JSON summary is unchanged byte for byte. =status=
and =replay= in Org add one =- pending_repair ::= line after the journal
position; the rendered =run-summary.org= projection itself is untouched. The
legacy =list --json= rows carry the same boolean =list --root= carries, and the
legacy Org table gained a =Repair= column (=yes=, =no=, or =-= for a row that
could not be read). Reporting is not repairing: the plan belongs to the Writer,
and no read truncates a tail, advances a receipt or writes a projection.

* Watch
=ai-orchestrator status [--json] --watch <run-dir> [--interval-ms <n>] [--for-ms <n>]=
and =ai-orchestrator list --root <runs-root> [--json] --watch [--interval-ms <n>] [--for-ms <n>]=
re-run exactly the one-shot read of the same verb and write a rendering only
when that rendering CHANGES. The loop belongs to the invoking process: no
supervised worker, no scheduled timer, no subscription and no lock, so nothing
survives the process and nothing can outlive a run it observes. It ends on a
terminal recorded status (=completed=, =cancelled=, =failed=,
=budget_exhausted=), on the =--for-ms= horizon, or when the operator interrupts
the foreground process; a listing has no terminal value, so it ends on the
horizon alone. =--interval-ms= defaults to 1000 and is bounded by 3600000;
=--for-ms= is bounded by 86400000. A read failure is written to stderr as the
verb's own reason map and the loop continues, so a torn tail or a receipt lost
during a live run does not end the watch. The loop itself exits 0.

* Replay
=ai-orchestrator replay <run-dir> [--json] [--to-seq <n>]= folds the verified
journal prefix and renders it exactly as =status= does. Without =--to-seq= it
is provably the =status= answer. With =--to-seq N= it answers the recorded
state as of sequence N, folded from the first N verified lines; an N above the
last verified sequence exits 66 with =replay_seq_out_of_range= naming both
sequences, and N below 1 or non-numeric exits 64. A prefix is a read and not a
repair: a torn journal still reports the pending plan for the whole file.

* Limits and dependencies
This is a one-shot journal inventory, not an atomic snapshot across directories.
Each valid run is read twice to preserve the existing public Query list shape;
the displayed row comes entirely from the later summary. Filesystem reads have
no hard wall-time or memory bound. Existing trusted stationary-filesystem
assumptions apply: this does not add descriptor-level journal-leaf confinement
or protection against a hostile concurrent rename.

Persistent Projection.Index, multi-root aggregation, =explain=, console
integration and installed qualification remain separate units. Watch and replay
are delivered above; neither adds a cache, a subscription, a change notification
or any cross-process view of liveness, and a watch is exactly a repeated read.
This operation does not depend on mounted start/resume, live transport or Ash.

* Acceptance mapping
=test/cli/cli_discovery_test.exs= exercises:
- D1 explicit root selection, deterministic ordering, both flag orders and relative roots.
- D2 legacy empty output and sanitized missing/unreadable explicit roots.
- D3 projection independence and chained-byte corruption.
- D4/D9 pending repair without changed files, bytes, receipts, locks or projections;
  a read-only filesystem seam has no write callbacks.
- D5 valid and corrupt siblings with closed per-row failures.
- D6 direct/compound escaping links and physical symlink/parent traversal.
- D7 duplicate durable identities, fresh invocations and failed second-read invalidation.
- D8 private error/content canaries, inert Org output and unsupported filename encodings.
  APFS rejects non-UTF8 fixture names with eilseq; on that platform the row checks
  a rejected explicit path, while the invalid directory-name discovery case runs
  on filesystems that permit it.
- D10 malformed argv refusals.

=test/cli/cli_test.exs= pins the pending-repair reporting of =status= and the
legacy =list= against an unchanged torn journal. =test/cli/cli_watch_test.exs=
exercises W1 successive values ending on the terminal status, W2 one rendering
for an unchanged journal with deleted and lagging projections, W3 a read
failure reported once while the loop keeps reading, W4 the explicit-root
listing loop, W5 the bounded horizon and W6 malformed watch argv.
=test/cli/cli_replay_test.exs= exercises R1 equality with =status=, R2 each
prefix, R3 the out-of-range refusal, R4 projection independence, R5 a torn
tail and R6 malformed replay argv.

Existing CLI tests and the relevant public Query preservation, path and repair
controls remain compatibility checks. This contract does not claim a full
core gate, hosted CI, Linux filename qualification or installed-service result.
