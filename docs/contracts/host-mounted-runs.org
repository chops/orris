endpoint, daemon mode, restart policy, live mounted cancellation, gating the producer before worker birth (needs a
Run seam), and installed-runtime changes.

* Scope
One BEAM. A mounted run is a run subtree that is an Application-root descendant, owned by ONE responsive process,
started and stopped through the host, whose result is read by any caller. Foreground runs (=Run.Executor.execute/2=,
=Host.Executor.execute/2=, the CLI) are unchanged: same spawn-unlinked owner, caller monitor, =:caller_gone=,
owner-resident barrier and admission/cleanup contracts. Cross-process views, endpoints, daemon mode, restart policy,
live cancellation of a mounted run, projection index and packaging stay outside.

* Supervision layout
=AiOrchestrator.Application.children/0= = =[Journal.Ownership, Host.Supervisor, Host.Monitor]=, =rest_for_one=.
- =Host.Supervisor= :: a DynamicSupervisor (=start_link(name: name | nil)=); children =Host.RunOwner=, =restart: :temporary=,
  =shutdown: child_shutdown_ms= (default 60_000; a seam). It terminates children concurrently (one timer per shutdown value).
- =Host.Monitor= is LAST: its restart restarts no run tree; it reconciles from the tree (section 5).
- Ownership loss cascades every mounted tree through the owners' =terminate/3=.

* The owner: =AiOrchestrator.Host.RunOwner= (a =:gen_statem=)
- It is the linked parent of =Run.Supervisor= (it calls =Run.Supervisor.start_link= from its =:starting= state). =init/1=
  returns BEFORE that call: the supervisor's start acknowledgment never waits for the run.
- Identities are held in the owner's own data only: the supervisor/server/work/writer from =which_children= after start,
  the worker from the =run_worker_registered= handoff EVENT. There are no progress messages and no second holder.
- The user barrier of a MOUNTED run executes in a linked+monitored helper process; its result is an event. Inside the
  barrier =self()= is the helper and =payload.owner= is the owner. This is a mounted-route semantic, stated here;
  the foreground barrier stays owner-resident (H-6a).
- The PARENT's EXIT reaches =terminate/3= (OTP intercepts it; it is never an event) in every state; =terminate/3= runs the
  teardown protocol of section 4 and answers waiters recorded before it began. A =:kill= collapses the subtree by links.
- States: =:starting= (the only synchronous phase: while =Run.Supervisor.start_link= is blocked the owner is NOT responsive;
  the gap ends when the Writer's acquire returns or fails, bounded by the Writer's acquire budget) -> =:handoff= (state
  timeout = handoff budget) -> =:barrier_handoff= -> =:barrier_subtree= -> =:awaiting= -> =:terminal=; teardown is entered
  from any state by =terminate/3=, an owner failure, or the subtree's EXIT (=run_server_down=).
- Privacy: =format_status= hides config, owned map and result; helper crashes are reported without run directory,
  tokens or config bytes (canary rows).

* Host API (in-VM; =host:= seams =%{supervisor, monitor, ownership}= default the Application instances)
- =Host.mount(command, context, opts) :: {:ok, handle} | {:error, closed}= — validation = =Run.Executor.prepare/2=
  (the existing order, without starting); then =DynamicSupervisor.start_child=. Returns as soon as the child is started
  (state =:starting=). =handle = %{run_dir, run_id, owner, ref}=.
- =Host.ready(handle, timeout) :: {:ok, %{generation, supervisor, server, writer, worker}} | {:error, closed}= — WAIT-ONLY:
  answers when the =:subtree_started= barrier RESULT is =:ok= (the owner entered =:awaiting=), or an earlier closed
  refusal/owner failure; ={:error, %{clause: "ready_timeout"}}= leaves the tree untouched. Ready proves the barrier
  returned; it does NOT prove registry visibility (registration is an asynchronous, fail-soft cast).
- =Host.await(handle, timeout)= — the =Run.Executor= result shape, cached in =:terminal=. Waiters: each recorded with a
  monitor on the caller AND a deadline = the caller's timeout; expiry is TIMER-DRIVEN (a =state_timeout=/timer of the
  owner), independent of any later event: a live caller whose call timed out is removed within its deadline; a dead
  caller is removed on DOWN; a valid waiter stays until the result. ={:error, %{clause: "await_timeout"}}= never cancels.
  An await that reaches an owner already in =terminate/3= or gone answers ={:error, %{clause: "run_host_owner_down"}}=.
- =Host.stop(handle, timeout)= — SYNCHRONOUS, never an unconditional =:ok=. The stop is an ACKNOWLEDGED protocol: a
  detached stop agent (never linked to the caller, not bounded by the caller's wait) sends the owner a
  =stop_request= naming the caller and its deadline; the owner answers from any responsive state, =:retained= for a
  terminal owner (retention kept, nothing terminated) or =:stopping= after it has recorded the stopper (caller
  monitor + deadline) and armed its OWN teardown as its next internal event, so the obligation lives in the owner
  regardless of the caller's wait. LIFECYCLE ARBITRATION: the owner's own word (=:retained= / =:stopping=) always wins
  and is awaited for the whole shared bound (the request is sent once). Evidence gathered while the owner is silent,
  (a) its =:sys= word (a suspended terminal owner still answers and is kept; any other reported phase is active/startup)
  and (b) runtime evidence it cannot withhold, a live =Run.Supervisor= still LINKED to it (its =$initial_call=, set by
  =proc_lib= before init, so a Writer blocked in acquire counts) proving the subtree is not torn down and nothing is
  retained, NEVER authorises destruction before the bound: it only decides the fate of an owner STILL silent at the
  bound, and a sampled phase can therefore never be acted upon after it became obsolete. At the bound the owner is
  FROZEN (scheduler-level suspension, so it can neither answer nor transition while the decision is taken); a reply it
  has already sent is honoured (the owner replies before it informs the caller, so no reply means the caller was told
  nothing); the link evidence is re-read under the freeze; and only a still-linked, still-silent owner that the host's
  supervisor confirmed as its child (bounded =which_children=) is killed, reported unproven. Everything else is resumed
  UNTOUCHED and reported unproven (an owner blocked inside a system callback is indistinguishable from a blocked
  startup by its answers alone; a wait can never authorise the loss of a cached result). Answers ={:ok, :stopped}= when teardown completed with every owned DOWN
  observed, ={:error, %{clause: "run_executor_teardown_incomplete", survivors: n}}= when a join was not observed,
  ={:error, %{clause: "run_host_stop_unproven"}}= when the bound expired without a proven stop (an owner proven active
  was killed by the supervisor; an owner without evidence was left as it was; no descendant/disk evidence is claimed:
  the caller observes =RunLock.owner= and =Ownership.status= itself). After an
  active stop the owner is GONE: a second active-stop call answers =run_host_owner_down=. Stop on a retained
  =:terminal= owner is idempotent =:ok= and preserves the cached result. Stop journals nothing.
- =Host.mounted(host, timeout, batch: n)= — ALL blocking work (the =which_children= discovery and every per-owner status)
  runs inside ONE absolute deadline; discovery and every per-owner query are unlinked monitored workers whose
  failure is a closed result (a caller is never exited); each owner costs ONE =:sys= leg. Owners are queried in
  batches of =n= (default: ALL at once, =batch: :all=; a finite batch is a supported option); within the ACTIVE batch the queries are CONCURRENT and each is bounded by what REMAINS of
  the deadline, never by a fresh per-query or per-batch budget, so within the default all-at-once case a responsive
  owner is reported regardless of the supervisor's child order and stalled owners cost only the remaining time;
  owners in batches not yet started when the common deadline expires are reported =:unknown= (MR-15 exercises the
  default single batch only). Partial results are the contract:
  owners that did not answer in time are listed with =phase: :unknown=; the listing element is
  =%{run_dir, run_id, owner, phase}=; a supervisor that does not answer within the deadline yields
  ={:error, %{clause: "host_supervisor_unavailable"}}=.
- =Host.census(opts) :: {:ok, %{census: :pending | :complete, skipped: n}}= — a NEW function; every slice-1 status,
  lookup and collision shape is unchanged (parity preserved, no additive field on them). Like status/lookup it is a
  bounded call (=timeout:=, default 1_000) that never blocks the Monitor.
- =Host.stop(handle, timeout)= budget: the caller's =timeout= bounds the WHOLE call as ONE absolute deadline (an agent
  death mid-wait continues the same deadline); the child's configured shutdown is ONE shared bound for the request wait,
  the evidence legs and the teardown, measured from the stop, never restarted or extended by a stop call, and no probe
  budget inside it exceeds it (small injected bounds shrink the probes; there is no floor). When the caller's budget elapses
  first the call answers ={:error, %{clause: "run_host_stop_timeout"}}= and the teardown continues to its own
  outcome (readable by a later await while the owner lives; otherwise =run_host_owner_down=).
- Test-only observation seams (declared here so the rows are honest; not an operator API): =Host.RunOwner.inspect(owner)=
  answers =%{phase, waiters, handoff_ref, owned: [roles]}= through =:sys.get_state= (a system message: it is NOT an owner
  event and therefore cannot trigger any lazy behaviour; waiter expiry is timer-driven and observable through it);
  the census request the Monitor sends is ={:census, ref, monitor}= and the reply an owner sends is
  ={:census_reply, ref, record, phase}=; a reply is ELIGIBLE only while its request reference is still pending in the
  Monitor (the census has not completed); before applying an eligible reply the Monitor confirms the owner's phase
  with a bounded =inspect= (a reply the owner does not confirm, or whose owner reports =:terminal=, is dropped:
  owner-alive alone is never sufficient); a reply whose request expired at the census deadline may be dropped.
  =Host.mounted(host, timeout, batch: n)= exposes the discovery batch size for tests; =census_timeout:= on
  =Host.Monitor.start_link= injects the census deadline for tests. Mounted-only handoff seam: the mount context key
  =:handoff_relay= (a pid) makes the owner register =%{owner_handoff: {relay, ref}}= instead of =self()=, and sends the
  relay ={:relay_owner, owner}=; the relay is test-owned and forwards the Server's real
  ={:run_worker_registered, ref, worker, server}= to the owner only when released, so rows can hold the identity at
  the EMISSION boundary without any post-notification suspension. Gating the producer BEFORE worker birth would need
  a Run seam and is not claimed by this contract.
- Helper escapes: the mounted barrier helper runs the user barrier under =try/catch= and reports
  ={:barrier_escape, kind, class, digest}= (the contract's =Diagnostic= result class and digest) to the owner; the
  helper never crashes with a raw reason, so no crash report can carry exception text or config bytes.

* 4. Result lifetime, teardown, budgets
- Active tree ends at the result (Server reply -> observed close for ={:ok, map}= only -> teardown) or at =terminate/3=.
  At that instant the owner unregisters its Monitor record explicitly (DOWN cleanup remains a backstop), stores the
  result, enters =:terminal=.
- Retention: =retention_ms= (default 60_000; seam): every await answers the same value; then the owner exits =:normal=
  and later calls answer =run_host_owner_down=. A parent shutdown ends retention at once. No second result store.
- Teardown protocol (one implementation, shared with the foreground owner after the Run refactor): kill+join the
  helper (its join has its own budget; an unobserved helper join is a survivor, never silently =:ok=); orderly
  =Supervisor.stop= (stop budget); kill every still-live owned pid; join each (join budget); then the late-identity
  sweep: because the Server (the only producer of =run_worker_registered=) is dead after the orderly stop/kill, one
  mailbox sweep after the joins is complete and finite: the hosted owner drains every queued identity carrying its
  handoff reference (including those that arrived during the teardown), kills and joins each, and counts an unobserved
  join as a survivor; an identity that reaches a RETAINED terminal owner is collected at once. Neither
  =Run.Server= nor =Run.Worker= traps exits, so a producer that is stopped can never send a later identity. With =Run= untouched the producer cannot be gated before birth; the rows therefore gate at the
  emission boundary through the =:handoff_relay= seam: never DELIVERED (the relay holds the real emission, the owner
  acknowledges =:handoff= with no =:worker=, stop joins the producer's DOWN, a later release is inert) and produced but
  unconsumed (owner suspended, relay released, shutdown sweeps the real worker). An identity message carrying the owner's handoff reference that arrives in any state other than
  =:handoff= is RETAINED by the owner (reported as the =:late= role by =inspect=, never dropped and never acted on) and
  is killed and joined by the teardown sweep; the synthetic-identity injection while a run is held is the separately
  labelled witness of that rule.
  Survivors -> =run_executor_teardown_incomplete=; an unanswered Writer close for an ok result -> =close_unproven=.
- Budgets (seams with production defaults): close 15_000, stop 15_000, join 5_000 per pid, handoff 5_000, helper join
  1_000; post-phase teardown worst case = 15 + 15 + 5 x 5 + 1 = 56 s; =child_shutdown_ms= 60_000. Whole-stop deadline =
  =child_shutdown_ms=; a never-released startup (the Writer never returns from acquire) is stopped by the supervisor's
  kill at that deadline and reported =run_host_stop_unproven=. Startup is explicitly NOT proven finite: a Writer whose
  acquire never returns is stopped only by the supervisor's kill, after which the caller must observe the disk lock
  and the arbiter itself (and, while the acquire is blocked, that arbiter answers =ownership_unavailable=, not =:none=);
  =ready= is wait-only.

* 5. Monitor census and discovery
- On init the Monitor spawns a monitored census Task and returns; the Task performs the =which_children= discovery and
  sends asynchronous census requests in batches of 64; the whole census (discovery included) is bounded by
  =census_timeout= (1_000 ms) measured from init; at the deadline the Task is killed and =census= is =:complete= with
  =skipped= = owners not answered. Partial knowledge stays partial: absence remains unknown (R7).
- Census replies are applied as registrations under the registration rules, an eligibility rule and a terminal
  rule: a reply is eligible only while its request is pending in the CURRENT census epoch (replies for expired
  requests may be dropped); the Monitor confirms the owner's phase in a bounded linked task under the common census
  deadline and stays responsive throughout (lookups and the deadline are never queued behind a confirmation); when
  the confirmation returns, eligibility, the owner and the generation are re-checked and a confirmed reply never
  displaces a live different owner or a higher generation (each rule independently); every confirmation in flight is
  correlated with its owner and directory, and an unregister naming that owner (registered or not), a DOWN dropping
  that owner's entry, or a fresher registration of that directory INVALIDATES it (its result is discarded on arrival
  and it is not counted as skipped), while
  a result arriving after the absolute census deadline is counted skipped rather than applied, so a delayed
  pre-terminal ACTIVE confirmation can never resurrect an entry unregistered in the meantime; the discovery
  task is linked to the Monitor so a Monitor
  death cannot orphan it, and each batch's pending references are announced by an acknowledged call before its
  requests are sent; a reply whose
  owner does not confirm, or reports =:terminal= (the tree already torn down), is dropped, so a retained terminal
  owner never resurrects an unregistered entry even when the reply is a genuinely correlated ACTIVE fact; a live
  different owner or a higher generation is never displaced. The rows exercise exactly that with the deadline
  injected long: a positive control proves an eligible active fact for a live suspended owner IS applied, then the
  same kind of fact is delivered after completion + unregister (retention keeps the owner) and after replacement
  (stop + remount) and must be dropped; the after-deadline case is kept separate.
- Owners never wait on the Monitor (registration is a cast).

* 6. Injected arbiter (the passthrough that does not exist yet; contract + RED now, code after review)
Today =Run.Supervisor= gives the Writer only =fs=/=clock= and =Run.Server= discovers through the global
=Journal.Ownership=, so an injected arbiter cannot reach a run subtree. The contract requires: =config.opts[:ownership]=
(=[server: name | pid, acquire_timeout: ms]=) reaches the Writer (=writer_opts=) and the Server's discovery, and the
same arbiter is used by =Host.Executor='s registration generation lookup and by =Host.status= when the caller passes
=ownership:=. Bounded Run paths: =run/executor.ex= (=prepare/2=), =run/executor/owner.ex= (shared exported helpers),
=run/supervisor.ex= and =run/server.ex= (passthrough). RED rows RP-1..RP-3 fail today on BEHAVIOUR (the global arbiter
receives the registration), not on a missing module: that attribution is part of the rows.

* 7. Lock guarantees (scoped; measured with real Writer/Recovery.acquire, never with =Recovery.evidence=, which reads
  only the journal)
- G-lock-1 (responsive): after =Host.stop= or the Ownership-loss cascade with a responsive Writer and FS: =Writer.close=
  /=terminate= released the disk lock (=RunLock.owner= =:none=), the arbiter record is retired (=:none=), and a real
  =Writer.open= / =Run.Recovery.acquire= on the directory succeeds and is closed with =:ok=.
- G-lock-2 (failure injection): a failed lock-release leg (=FaultFs= on the tombstone link) answers =close_failed= naming
  the =lock= leg; the arbiter record is RETAINED (it is the only authority that can reclaim); a killed Writer (no
  terminate) leaves the lock and the record; the next real acquire under the same arbiter reclaims or answers the
  arbiter's own closed =reclaim_failed=; under a fresh arbiter the same-OS-process holder is refused =run_locked=. The
  rows assert the exact clause the path produces and that no second Writer ever opened; they never relax a failed
  observation into success.
